## 1. 总工期与原则

| 项 | 约定 |
|----|------|
| 总工期 | **8–10 周**（含联调与测试缓冲） |
| 中位建议 | **约 9 周** |
| 调整依据 | M1 工具面大、需加测试；M2 拆为角色卡 → PPT；M3 支付后置为可选 |
| 通用交付 | 每阶段：**可演示包 + 接口/变更说明 + 已知问题清单 + 完成标准勾选表** |

---

## 2. 成功指标（上线 4 周内）

| 指标 | 目标 |
|------|------|
| 任务成功率 | ≥ 95%（排除用户取消与用户错误） |
| P95 压缩/合并完成时间 | ≤ 60s（单任务输入合计 ≤20MB） |
| 日活工具完成次数 | 可观测，建立基线 |
| AI 任务有结果可下载率 | ≥ 90% |

## 3. 里程碑排期

### 3.1 总览表

| 里程碑 | 周期 | 累计周（参考） | 目标摘要 | 完成标准（DoD） | 关键交付物 |
|--------|------|----------------|----------|-----------------|-----------|
| **M0 基建** | **1 周** | 第 1 周 | 工程骨架、登录、空任务链路 | ① 本地一键起服可演示 ② 冒烟用例通过 ③ 脚手架/环境文档齐全 | docker-compose、OpenAPI、空 Celery 任务、错误码初表 |
| **M1 MVP 工具** | **3–4 周** | 第 2–5 周 | 转 PDF / 压缩 / 合并 + 任务中心 + 额度 | ① 三条工具可演示 ② **功能+压测通过** ③ 接口与已知问题文档齐全 | 体验版、压测报告、监控告警、PPT POC Go/No-Go |
| **M2a 角色卡** | **1.5–2 周** | 第 5.5–7 周 | AI 角色卡：生成→本地编辑→出图 | ① 完整链路可演示 ② 审核与额度用例通过 ③ Prompt/接口文档齐全 | 角色卡页、双向审核、出图样例 |
| **M2b PPT** | **1.5–2 周** | 第 7–9 周 | 大纲二编 → 模板导出（依赖 M1 POC=Go） | ① 端到端可演示 ② 模板填充回归通过 ③ 模板说明文档齐全；**POC=No-Go 则砍掉/降级并书面记录** | pptx 下载、大纲编辑页 |
| **M3 小说（支付可选）** | **1–1.5 周** | 第 8–10 周 | 分章小说 + 导出；商业化可选 | ① 小说主路径可演示 ② token 上限与审核用例通过 ③ 文档齐全；**支付未做不阻塞 M3 验收** | TXT 导出、额度策略；支付为可选包 |

### 3.2 周次编排

```
W1        M0
W2–W5     M1（其中末 1 周侧重回归/压测；若赶工可压成 3 周）
W5.5–W7   M2a（可与 M1 收尾少量重叠，但不抢 M1 测试人力）
W7–W9     M2b（仅 POC=Go；否则跳过并进入 M3）
W9–W10    M3 小说；支付/会员 = 可选加时或 V1.1
```

| 总周数 | 拆分建议 |
|--------|----------|
| **8 周** | M1=3，M2a=1.5，M2b=1.5，M3=1（支付跳过） |
| **10 周** | M1=4（加缓冲测试），M2a=2，M2b=2，M3=1 |

### 3.3 分阶段说明

#### M0 — 基建（1 周）

- Monorepo、CI、环境变量规范、`oc_shared`（错误码与 `user_msg`）
- 微信登录、上传凭证（15min）、空任务链路（创建→入队→Worker 回写）
- **交付物**：docker-compose（MySQL+Redis+api+worker）、启动文档（[05](./05-启动步骤.md)）、OpenAPI、Celery 空任务、错误码初表
- **PPT 模板 POC**：已完成 → **[条件 Go](./known-issues/ppt-poc-go-nogo.md)**（不阻塞 M0/G1；M2b 用 1–2 套自研简模）

| 完成标准 | 具体含义 |
|----------|----------|
| 功能可演示 | 本机：登录 → 申请凭证 → 创建空任务 → 任务中心看到 succeeded |
| 测试通过 | M0 冒烟清单全绿（健康检查、入队、幂等键拒绝空值等） |
| 文档齐全 | README、`.env.example`、OpenAPI、错误码表、启动步骤 |

#### M1 — MVP 工具（3–4 周）

- 图片转 PDF、PDF 压缩、PDF 合并（蓝图 §3.3 边界）
- **额外已开做（蓝图 V1 可砍）**：Word/Office → PDF（`office_to_pdf`，依赖 LibreOffice）
- 任务中心、额度预扣/返还、幂等与并发上限
- 上传孤立清理、输入/输出 TTL、基础告警
- 重试 API、超时 `53001`（Worker + Beat sweep）、结果过期 `40016` / `GET .../download`
- **末周不少于 1 周**回归与压测；禁止「功能刚通就开 M2」

| 完成标准 | 具体含义 |
|----------|----------|
| 功能可演示 | 体验版：上传→三工具→下载；任务中心；额度不足/超时返还提示 |
| 测试通过 | 功能用例（加密 PDF、超限、重试、取消）+ **压测**（见 §5） |
| 文档齐全 | 接口说明、`scripts/load/` 压测报告、已知问题、**PPT POC Go/No-Go**（见 [G1_REPORT](../scripts/load/G1_REPORT.md)） |

#### M2a — 角色卡（1.5–2 周）

- 生成 → 本地编辑确认 → 出图；双向审核；差异化扣点

| 完成标准 | 具体含义 |
|----------|----------|
| 功能可演示 | 填写到出图分享全流程；审核拒绝有正确 `user_msg` |
| 测试通过 | 额度预扣 / 安全拒绝不返还 / 版本冲突（乐观锁）等用例 |
| 文档齐全 | Prompt 版本、角色卡 schema、接口与示例 payload |

#### M2b — PPT（1.5–2 周，依赖 M1 POC=Go）

- 大纲强制二次编辑 → 模板填充 → pptx 下载（1–2 套模板）
- POC=No-Go：取消或降级为「仅大纲导出」，工期释放给 M3；记入已知问题与蓝图 §1.4

| 完成标准 | 具体含义 |
|----------|----------|
| 功能可演示 | 主题→大纲编辑→生成→可下载 pptx |
| 测试通过 | 页数边界、缺大纲版本拒生成、超时返还等回归 |
| 文档齐全 | 模板字段映射、Prompt 版本；砍掉则有书面降级说明 |

#### M3 — 小说与收口（1–1.5 周；支付可选）

- **必须**：设定→大纲→分章/续写→TXT；token/章节上限；双向审核
- **可选**：微信支付/会员/运营后台最小集 → **V1.1 / M3-optional**，不阻塞 M3 验收
- 上架：隐私政策/用户协议、类目与 AI 开关策略

| 完成标准 | 具体含义 |
|----------|----------|
| 功能可演示 | 至少 2 章续写 + 导出 TXT；额度与超时表现正确 |
| 测试通过 | token 上限、审核拒绝、进行中任务上限等用例 |
| 文档齐全 | 小说限制说明、上架检查清单；支付未做标注「可选未交付」即可过 M3 |

### 3.4 阶段门禁（Gate）

| Gate | 时机 | 不过则 |
|------|------|--------|
| G0 | M0 结束 | 不得开始 M1 业务开发 |
| G1 | M1 结束（含压测） | 不得开始 M2a；工具体验版不提审 |
| G2a | M2a 结束 | 可并行筹备 M2b；角色卡可进体验版 |
| G2b | M1 POC 结论 | **已出：条件 Go**；若产品改坚持精美多套 → 记 No-Go 跳过 M2b |
| G3 | M3 必须项结束 | 可申请提审；支付未完成不阻提审（若类目不依赖 IAP） |

## 4. 测试策略总览

工程强制规则（覆盖率、CI、MinIO 等）见开发规范 §10 / §9.5；本节给出**与排期绑定**的测试计划。

### 4.1 分层要求

| 层级 | 要求 | 主要归属里程碑 |
|------|------|----------------|
| 单测 | API 校验、额度预占/回滚并发、状态机流转 | M0 起持续；M1 加严 |
| 覆盖率 | `apps/api` 业务 + `oc_core`：**行 ≥ 80%**，**分支 ≥ 70%**（CI 卡控） | M1 Gate G1 前达标 |
| Worker | gs/soffice 可 mock；1–2 个黄金小文件集成；幂等投递 | M1 |
| 集成 | MinIO 模拟 COS、测试 Redis、测试库；本地可重复 | M0/M1 |
| 小程序 | idempotency / backoff / cache utils；页面人工用例 | 各阶段 |
| 回归冒烟 | 压缩/合并/转 PDF/角色卡 + 额度回退 | 每阶段结束 / 发版 |
| 压测 | 合并/压缩 P95、失败率、inflight≤3 | **M1 末周必须** |

禁止用用户真实上传文件当 fixture。

### 4.2 各里程碑测试清单（摘要）

#### M0 冒烟

- [x] `GET /healthz` 返回 `code=0`
- [x] `POST /v1/auth/wx-login` stub 可拿 token
- [x] `POST /v1/tasks` 无 `Idempotency-Key` → `40008`
- [x] 有幂等键时可入队；Worker 可见 `ping_task`（Redis 已启）并回写 `succeeded`
- [x] `uv run pytest -q` 通过
- [x] 按 [05-启动步骤](./05-启动步骤.md) 本机起服成功
- [x] `POST /v1/uploads/credential` stub 返回 `uploadId` + ≤15min 凭证
- [x] CI 工作流入库（`.github/workflows/ci.yml`：ruff / migrate / pytest / pip-audit）

#### M1 功能与压测

**功能：**

- [x] 图片转 PDF 主路径可下载（MinIO + 详情 `outputs[].downloadUrl` / 小程序「下载 PDF」）
- [x] Word 转 PDF 主路径可下载（需 LibreOffice；可选）— 实现已有；本机无 soffice 时失败文案正确
- [x] PDF 压缩 / 合并主路径可下载
- [x] 加密 PDF、超限、损坏文件 → 用户错误文案；**释预占不扣费**（转换器 + settle 单测）
- [x] 取消任务返还额度；超时 `53001` 返还（Worker soft/hard limit + Beat `sweep_timeouts`）
- [x] 重试次数上限、不可重试类型拒绝（`POST /v1/tasks/{id}/retry`）
- [x] 单用户进行中任务 ≤3
- [x] 结果过期后不可下载（`result_expired` / `40016`；`GET .../download`）

**压测（写入 `scripts/load/` + 报告）：**

- [x] 限制内压缩/合并 **P95 ≤ 60s** — 见 [G1_REPORT](../scripts/load/G1_REPORT.md)
- [x] 任务成功率（排除用户错误）可接受，失败可归因
- [x] 并发创建不突破 inflight=3；超额返回 `40005`（单测 + `scripts/load/run_inflight.py`）
- [x] 队列过载/繁忙时有明确拒绝（`40018` / `queue_overloaded`）
- [x] PPT 模板 POC 书面结论（[条件 Go](./known-issues/ppt-poc-go-nogo.md)）

#### M2a / M2b / M3

- 以 §3.3 各阶段「测试通过」行为准；AI 须覆盖双向审核、2000 字上限、Schema 重试失败落 `failed`。
- **M2a / G2a 通过（2026-09-09）**：演示主路径 `POST .../imagine` + 本地卡集；服务端 `generate`→`put`→`render`（预扣 3）；审核/乐观锁/额度用例见 `apps/api/tests/test_ai_character_card.py`；冒烟报告 [G2A_REPORT](../scripts/load/G2A_REPORT.md)；Prompt/schema 见 [08](./08-AI与Prompt规范.md)。
- **M2b 进行中**：`POST .../ppt/outline`（免费）→ `PUT`（`40012`）→ `POST .../ppt/generate`（预扣 5）；模板 `tpl_basic_01`；见 [08](./08-AI与Prompt规范.md) §4。

### 4.3 发版前测试门禁

与开发规范 §17 对齐，至少：

- [x] CI 全绿（lint、单测、覆盖率行 ≥80%；分支 ≥70% 仍建议继续补）— pytest `--cov-fail-under=80`
- [ ] `pip-audit` 无未豁免高危
- [ ] 监控面板有数据；`requestId` 可串 api→worker
- [x] 额度回退场景抽测通过（取消 / 用户错误 / 超时 settle 单测）
- [x] 体验版冒烟（当前已交付功能）— G1 工具 + G2a 角色卡（[G2A_REPORT](../scripts/load/G2A_REPORT.md)）
