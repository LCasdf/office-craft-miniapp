## 1. 项目概述

### 1.1 一句话定位

面向个人用户的微信小程序：**文件工具箱 + AI 轻创作台**，覆盖格式转换、PDF 处理、PPT/小说/角色卡生成。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| 好用 | 3 步内完成高频工具（上传 → 处理 → 下载） |
| 可控 | 大文件与 AI 任务异步化，进度可感知 |
| 可运营 | 额度、会员、任务历史可扩展 |
| 可合规 | 内容审核、隐私删除、用户协议齐全 |

### 1.3 非目标（本期不做）

- 不做在线协同编辑（Word/PPT 在线改稿）
- 不做完整写作 IDE / 长篇连载社区
- 不做跨端 App（可预留 uni-app，首期以微信为主）
- 不做本地端侧模型推理

### 1.4 V1 可弱化 / 可砍功能（明确边界）

下列能力**允许在 V1 砍掉或降级**，避免范围膨胀；砍前需在里程碑评审中勾选确认：

| 能力 | V1 建议 | 说明 |
|------|---------|------|
| Word/Markdown → PDF（F07） | 可砍 | 依赖 LibreOffice，运维重；MVP 不绑定 |
| 小说 DOCX 导出 | 降级为仅 TXT | DOCX 排版延后 |
| PPT 多套精美模板 | 降级为 1–2 套基础模板 | M1 末 POC；No-Go 则跳过 M2b |
| 角色卡高清海报多布局 | 降级为单模板出图 | 先保证 JSON + 一张分享图 |
| 任务 WebSocket 实时推送 | 砍 | MVP/V1 用轮询即可 |
| 会员支付与运营后台 | **可选 / V1.1** | 不阻塞 M3 与提审；先用每日免费额度 + 人工加白 |
| 小说「广场/公开分享」 | 砍 | 合规与审核成本高 |
| PDF 书签/目录保留、密码 PDF | 砍 | 合并/压缩遇加密文件直接用户错误失败 |
| 断点续传 / 分片上传 | 可砍 | V1 靠单文件大小上限规避 |
| 多语言界面 | 砍 | 仅中文 |

## 2. 用户与场景

### 2.1 目标用户

- 学生：作业 PDF 合并、压缩后上传
- 职场人：图片转 PDF、快速出 PPT 骨架
- 创作者：角色卡、短篇/分章小说草稿

### 2.2 核心用户旅程

```
发现入口 → 选工具 → 上传/填表单 → 确认参数
    → 提交任务 → 看进度 → 预览/下载/转发 →（可选）再次创作
```

### 2.3 成功指标（MVP）

| 指标 | 目标（上线 4 周内） |
|------|---------------------|
| 任务成功率 | ≥ 95%（排除用户取消与用户错误） |
| P95 压缩/合并完成时间 | ≤ 60s（单任务输入合计 ≤20MB） |
| 日活工具完成次数 | 可观测，建立基线 |
| AI 任务有结果可下载率 | ≥ 90% |

### 3.3 功能边界细则

#### F01 图片转 PDF

- 输入：jpg/png/webp，单次 ≤ 20 张，单张 ≤ 10MB
- 输出：PDF；输出对象 TTL 见 §4.8
- 参数：顺序、页面方向（自适应/竖向）

#### F02 PDF 压缩

- 输入：单个 PDF ≤ 50MB（MVP）
- 档位：`high` / `standard` / `extreme`
- 输出：展示压缩前后体积
- 加密/损坏 PDF：归为**用户错误**；按 §4.6 **释放预占、不扣费**

#### F03 PDF 合并（边界修正）

| 项 | 规则 |
|----|------|
| 文件数 | **2–10**（MVP；原 20 过大，易超时与内存暴涨） |
| 单文件大小 | ≤ 30MB |
| 合计大小 | ≤ **50MB** |
| 总页数 | ≤ **200**（Worker 预检；超限用户错误） |
| 顺序 | 前端可调整；提交顺序即合并顺序 |
| 加密 PDF | 任一文件带打开密码 → 整单失败，`error_class=user`，提示「含加密 PDF，请先解除保护」 |
| 损坏/非 PDF | 魔数校验失败 → 用户错误，指明文件名 |
| 书签/附件/注释 | **不保证保留**（V1 明文告知） |
| 超时 | **120s**（与 §4.3 `pdf_merge` 一致）；超时归 `timeout`，系统回退额度 |

#### F06 角色卡

- 字段：姓名、设定、性格、外貌、能力、口头禅、禁忌等
- 流程：AI 生成草稿 → **用户本地编辑确认** → 再出图/保存（禁止「生成完不可改直接定稿」）
- 输出：结构化 JSON + 分享图（PNG）
- **双向内容安全审核**（输入设定 + 输出文案/图）

#### F08 PPT

- 输入：主题、页数（5–15）、风格模板 ID
- **强制流程**：AI 出大纲 → **用户二次编辑并确认** → 才允许 `ppt/generate`
- 不做复杂动画与母版深度自定义（V1）
- M0/M1 前须完成「PPT 模板库 POC」（见 §6）

#### F09 小说

- 流程：设定 → 总纲 → 章纲 → 分章正文
- **Token / 长度上限**（可配置，默认）：
  - 设定+总纲：合计输入 ≤ 4k tokens 等价字符（约 6k 汉字内裁剪提示）
  - 单章正文生成：`max_output_tokens` ≤ 2048；超长章节拆多章，禁止一次打满
  - 单项目累计生成章节 ≤ 30（防刷）
- 导出：V1 至少 TXT；DOCX 可砍
- 双向内容审核

## 4. 技术架构蓝图

### 4.1 技术栈（已锁定）

| 层级 | 选型 | 备注 |
|------|------|------|
| 前端 | 微信原生小程序 + TypeScript | 或 Taro 3（若明确要多端再换） |
| 状态 | 小程序原生 + 轻量 store（如 mobx-miniprogram） | 避免过重 |
| 后端 API | **Python 3.11+ / FastAPI** | uvicorn；Pydantic v2 做请求校验 |
| ORM / 迁移 | SQLAlchemy 2.x + Alembic | 对齐 `docs/04-数据模型.md` |
| 队列 | **Redis + Celery**（默认） | 含重试、超时、**DLQ/死信路由**；见 ADR-0001 |
| Worker | **同一 Python 代码库 / Celery Worker** | 一任务一子进程隔离；镜像含 gs 等 |
| DB | MySQL 8（主）/ 本地可用 Postgres 仅作备选 | DDL 以 MySQL 为准 |
| 对象存储 | 腾讯云 COS | 输入/输出分 TTL |
| AI | 国内大模型 OpenAPI | API 进程内适配层，重活仍可异步化 |
| 监控 | structlog JSON + Prometheus/Grafana（或云监控） | 全链路 `task_id` / `request_id`；见开发规范 §11 |

**队列说明：** 默认 **Celery**（CPU/子进程型文件任务更成熟）。若未来以纯 asyncio 轻任务为主，可评估 ARQ，但不作为 MVP 默认。

**契约说明：** 权威 schema 在 Python 包 `packages/oc_shared`（Pydantic + 错误码）；OpenAPI 由 FastAPI 导出供小程序对照；小程序侧可手写薄 `services/api.ts` 或从 OpenAPI 生成。

### 4.3 任务状态机

```
pending → queued → running → succeeded
                         ↘ failed → (可选) retry → queued
         ↘ cancelled
         ↘ expired（结果过期后的展示态，见任务中心）
```

#### 通用规则

- 仅 `failed` 且 `retryable=true` 且未超最大重试次数时允许用户重试
- 终态任务文件按 §4.8 TTL 清理；DB 保留元数据与 `cost_quota`
- 进入 DLQ 的消息必须告警，禁止静默丢弃
- 创建成功即写入 `timeout_at` 的**处理时限基准**；进入 `running` 时刷新为 `started_at + type_timeout`（以 running 起算为准）

#### 分类型处理超时（自 `running` 起算）

| 任务类型 `type` | 超时阈值 | Celery `time_limit` 建议 | 说明 |
|-----------------|----------|--------------------------|------|
| `image_to_pdf` | **60s** | 60 / soft 50 | 多图时仍受张数上限约束 |
| `pdf_compress` | **60s** | 60 / soft 50 | 与产品 P95 SLO 对齐 |
| `pdf_merge` | **120s** | 120 / soft 100 | 多文件，宽于单文件压缩 |
| `office_to_pdf` | **180s** | 180 / soft 150 | LibreOffice 冷启动更慢（V1 可砍） |
| `character_card` | **120s** | 120 / soft 100 | 含模型 + 出图 |
| `ppt_generate` | **120s** | 120 / soft 100 | 含模板填充；大纲接口可同步短超时 |
| `novel_chapter` | **120s** | 120 / soft 100 | 受 max_tokens 限制 |
| 默认（未列出） | **90s** | 90 / soft 75 | 新类型必须先登记再上线 |

另设 **排队等待上限**：处于 `queued` 超过 **10 分钟**仍未消费 → 标记失败（`error_class=system`，`error_code=50002` 建议码 `queue_wait_timeout`），并按 §4.6 **返还额度**。

#### 超时后如何标记失败

1. **触发方（任一先发生即生效，需幂等写终态）**
   - Celery：`SoftTimeLimitExceeded` / `TimeLimitExceeded`（硬限制杀进程）
   - Worker 内对 gs/soffice 的子进程到达类型超时 → `SIGKILL`
   - 调度补偿：扫描 `status=running AND timeout_at < now()` 的僵尸任务并收口
2. **写库（同一事务或条件更新 `status IN (running,queued)`）**
   - `status = failed`
   - `error_class = timeout`（排队超时用 `system`）
   - `error_code = 53001`（`task_timeout`）；排队超时用 `50002`
   - `error_detail` = 内部摘要（超时秒数、信号、命令），**不返回前端**
   - `progress` 保持超时前值；`finished_at = now()`
   - `retryable = true`（受 §4.4 重试次数约束）
3. **资源与额度**
   - 确保子进程/临时文件已清理
   - 按 §4.6 **返还预扣额度**（`quota_settled=2`）
4. **用户可见**：`user_msg` 如「处理超时，额度已返还，请稍后重试」；可带 `requestId`/`taskId`

### 4.4 任务中心约束

| 项 | 规则 |
|----|------|
| 列表分页 | Cursor 分页：`GET /v1/tasks?cursor=&limit=`，默认 `limit=20`，最大 50 |
| 筛选 | 可选 `status` / `type`；默认近 30 天 |
| 过期表现 | 结果文件已清理：`status` 仍为 `succeeded`，但 `result_expired=true`，下载按钮禁用，文案「已过期，请重新处理」 |
| 最大重试 | 用户主动重试 ≤ **2** 次/任务；系统自动重试 ≤ **1** 次（仅可恢复的系统错误） |
| 不可重试 | `error_class=user`、内容安全拒绝、额度不足创建失败 |
| 并发排队 | 单用户同时处于 `pending|queued|running` 的任务数 ≤ **3**（可配置）；超出返回用户错误并引导去任务中心 |

### 4.5 核心数据实体（逻辑模型）

> 物理 DDL、索引与 3NF 拆表见 [`docs/04-数据模型.md`](./04-数据模型.md)。  
> 下表为逻辑字段；类型按 **MySQL 8** 表述。时间默认 `DATETIME(3)`（毫秒），主键均为 `BIGINT UNSIGNED`。

#### User（`users`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED | 主键 |
| openid | VARCHAR(64) | 微信 openid，唯一 |
| unionid | VARCHAR(64) NULL | 微信 unionid，可空唯一 |
| nickname | VARCHAR(64) NULL | 昵称（可选缓存） |
| avatar_url | VARCHAR(512) NULL | 头像 URL（可选缓存） |
| status | TINYINT | 1=正常 0=禁用 |
| created_at | DATETIME(3) | 注册时间 |
| updated_at | DATETIME(3) | 更新时间 |

#### Quota（`quotas`，与 User 1:1）

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | BIGINT UNSIGNED | PK，FK → users.id |
| daily_quota_limit | INT UNSIGNED | 每日免费额度上限 |
| daily_used | INT UNSIGNED | **当日已用点数**；与 `daily_used_date` 配对 |
| daily_used_date | DATE | **daily_used 所属自然日**（Asia/Shanghai）；跨日则懒重置为 0 |
| total_used | BIGINT UNSIGNED | **历史累计已用点数**（不含已回退） |
| frozen_quota | INT UNSIGNED | 预占中尚未结算的点数 |
| vip_balance | INT UNSIGNED | 会员/加购余额 |
| vip_expire_at | DATETIME(3) NULL | 会员到期；空表示非会员 |
| updated_at | DATETIME(3) | 更新时间 |

可用额度（逻辑）：若 `daily_used_date < 今日` 则视 `daily_used=0`；`available = (daily_quota_limit - daily_used) + vip_balance - frozen_quota`。

#### Task（`tasks`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED | 主键 |
| public_id | CHAR(26) | 对外 ULID/Snowflake，唯一 |
| user_id | BIGINT UNSIGNED | FK → users.id |
| type | VARCHAR(32) | 任务类型枚举字符串 |
| status | VARCHAR(16) | pending/queued/running/succeeded/failed/cancelled |
| progress | TINYINT UNSIGNED | 0–100 |
| error_code | INT NULL | 业务错误码；成功为空 |
| error_class | VARCHAR(16) NULL | user/system/timeout/safety |
| error_detail | TEXT NULL | **内部诊断**（堆栈摘要/stderr），禁止直接返回前端 |
| retry_count | TINYINT UNSIGNED | 已重试次数（用户+系统合计或分列见 DDL 注释） |
| cost_quota | INT UNSIGNED | 本单预占/扣减点数 |
| quota_settled | TINYINT | 0=预占中 1=已实扣 2=已回退 |
| input_meta | JSON NULL | 输入参数摘要（页数、档位等），不含文件正文 |
| output_meta | JSON NULL | 输出摘要（大小、页数、cos 引用等） |
| idempotency_key | VARCHAR(64) NULL | 幂等键；与 user_id 唯一 |
| timeout_at | DATETIME(3) NULL | **计划超时时刻**；调度/Worker 据此 kill |
| result_expires_at | DATETIME(3) NULL | 结果过期时间（业务 TTL） |
| started_at | DATETIME(3) NULL | 进入 running 时间 |
| finished_at | DATETIME(3) NULL | 终态时间 |
| created_at | DATETIME(3) | 创建时间 |
| updated_at | DATETIME(3) | 更新时间 |

#### Asset（`assets`）与内容寻址（`storage_objects`）

为满足 **sha256 去重** 且符合 3NF：文件字节属性落在 `storage_objects`，`assets` 只表达「任务与文件的关系」。

**Asset（逻辑视图字段）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED | 主键 |
| task_id | BIGINT UNSIGNED | FK → tasks.id |
| storage_object_id | BIGINT UNSIGNED | FK → storage_objects.id |
| kind | VARCHAR(16) | input / output |
| original_filename | VARCHAR(255) NULL | 用户侧文件名（随关系变，不放入 storage） |
| ttl_expire_at | DATETIME(3) | 业务侧过期时间 |
| created_at | DATETIME(3) | 创建时间 |
| sha256 | CHAR(64) | **逻辑字段**：来自关联的 storage_objects.sha256 |

**storage_objects（物理去重表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED | 主键 |
| sha256 | CHAR(64) | 内容哈希，**全局唯一**，用于去重 |
| size_bytes | BIGINT UNSIGNED | 字节大小 |
| mime | VARCHAR(128) | MIME |
| cos_key | VARCHAR(512) | 对象存储键（去重命中可复用） |
| ref_count | INT UNSIGNED | 引用计数，辅助清理 |
| created_at | DATETIME(3) | 首次写入时间 |

#### AiSession（`ai_sessions`）+ 消息行（`ai_messages`）

会话与消息拆分，避免重复组违反 1NF/3NF。

| 字段（ai_sessions） | 类型 | 说明 |
|---------------------|------|------|
| id | BIGINT UNSIGNED | 主键 |
| user_id | BIGINT UNSIGNED | FK → users.id |

### 4.6 额度系统

#### 重置规则

- 每日免费额度按 **Asia/Shanghai 自然日**（待决策见 §9）
- 懒重置：若 `quotas.daily_used_date < 今日`，则将 `daily_used` 置 `0` 并更新 `daily_used_date=今日`
- `total_used` **不因跨日重置而清零**；回退额度时 `total_used` 相应减少（不低于 0）
- 不依赖定时任务作为唯一重置路径；定时任务仅作对齐补偿（可选）

#### 差异化扣减（默认点数值，可配置）

| 任务类型 | 扣额度（点） |
|----------|-------------|
| 图片转 PDF | 1 |
| PDF 压缩 | 1 |
| PDF 合并 | 2 |
| Office → PDF | 2 |
| 角色卡生成（含出图） | 3 |
| PPT 大纲 | 0 或 1（产品定；建议大纲免费、生成收费） |
| PPT 生成 | 5 |
| 小说单章 | 4 |

#### 扣减时机（预扣 / 实扣 / 返还）

**原则：任务创建成功后立即预扣额度；成功则转实扣；失败（可返还类）或取消则返还。**

```
POST /v1/tasks 校验通过（含幂等未命中）
  → 校验余额 ≥ cost_quota
  → 事务内：写入 task(pending) + 预扣（frozen_quota += cost，或等价记账）
  → quota_settled = 0（预占中）
  → 入队 queued
        │
        ├─ succeeded
        │     → 预占转实扣：frozen -= cost；daily_used/vip 实扣；total_used += cost
        │     → quota_settled = 1
        │
        ├─ failed + error_class ∈ {system, timeout}
        │     → 返还预扣：frozen -= cost；quota_settled = 2
        │
        ├─ failed + error_class ∈ {user}（输入文件问题：加密/损坏/类型不符等）
        │     → 释放预占、不扣费；quota_settled = 2
        │
        ├─ failed + error_class = safety
        │     → 默认不返还（防刷审）；quota_settled = 1
        │
        └─ cancelled
              → 一律返还预扣（含 running 中取消且未产出成功结果）
              → quota_settled = 2
```

补充约定：

- **创建失败**（参数错误、额度不足、并发上限、幂等冲突等）**不落任务或不预扣**；幂等命中已存在任务则不重复扣。
- 回退/实扣必须写 `operation_logs`，金额与 `task.cost_quota` 一致。
- 用户重试：仅 `retryable` 且已返还的任务；重试接口再次预扣；`safety` 默认禁止重试。
- 编码细则见 `docs/02-开发规范.md` §5.8（额度仅 API 变更，Worker 禁改 quotas）。

#### 额度耗尽交互

1. 工具页主按钮旁展示剩余点数  
2. 余额 < 本单 `cost`：主按钮禁用或点击后弹窗「今日额度已用完」  
3. 弹窗提供：查看任务中心 / 明日再来 /（若有）开通会员  
4. API 返回 `code=40003`，`user_msg` 明确可读，禁止只回 `quota exceeded`

### 4.7 上传链路边界

| 项 | 规则 |
|----|------|
| 凭证有效期 | 临时密钥 / 预签名 **≤ 15 分钟**；仅授权到用户前缀路径 |
| 额度预校验 | `POST /v1/uploads/credential` 时传入 `taskType`（或预估 cost），余额不足则**拒发凭证** |
| 并发 | 申请凭证前同样检查「单用户进行中任务 ≤ 3」；可选：未建任务的「上传中」会话也计入软限制 |
| 路径 | `{env}/{userId}/uploads/{uploadId}/...`，建任务后再关联到 `taskId` |
| 孤立垃圾清理 | 超过 **6h** 仍未绑定成功任务的 upload 前缀，定时任务删除 COS 对象并记日志（与输入 TTL 对齐） |
| 直传后建任务 | `POST /v1/tasks` 校验 object 归属与大小；失败不留永久垃圾（依赖上述清理） |

### 4.8 对象存储 TTL

| 对象类型 | TTL | 说明 |
|----------|-----|------|
| 输入文件（`kind=input`） | **6h**（自上传或建任务起） | 与开发规范 §6.6 一致；可提前主动删除 |
| 输出文件（`kind=output`） | **24h**（自任务成功起） | 与任务中心「过期」对齐 |
| 上传未绑定对象 | **6h** | 孤立清理（凭证已发未建任务） |
| 角色卡封面（若允许长期保存） | **30d** 或用户删除为止 | 待决策；MVP 可先跟 24h，卡片 JSON 留在 DB |

生命周期规则写在 COS / 定时清理双重保险；DB `assets.ttl_expire_at` 为权威业务时间。

### 4.9 接口幂等与并发

详见 §4.11「创建任务与幂等键」。摘要：

| 项 | 规则 |
|----|------|
| 幂等键 | `POST /v1/tasks` 等扣费创建接口：**请求头 `Idempotency-Key`（必填）** |
| 幂等窗口 | 24h；同用户同 Key → **同一 task / 同一响应语义** |
| 并发排队 | 单用户 `pending+queued+running` ≤ **3** |
| 冲突码 | `40005` 进行中过多；`40007` 同 Key 不同请求体 |

### 4.10 错误码与用户可见文案体系

#### 响应包络（强制）

```json
{
  "code": 40001,
  "message": "invalid_pdf_encrypted",
  "user_msg": "合并失败：其中《作业.pdf》为加密文件，请先解除保护后再试",
  "data": null,
  "requestId": "req_xxx",
  "taskId": "tsk_xxx"
}
```

| 字段 | 说明 |
|------|------|
| `code` | 数字错误码，前后端契约 |
| `message` | 稳定机器可读字符串（英文 snake），用于日志与埋点 |
| `user_msg` | **用户可见中文**；前端默认只展示该字段 |
| `requestId` | 全链路请求 ID |
| `taskId` | 与任务相关时必填；无任务可省略 |

#### 错误分类 `error_class`

| class | 含义 | 额度 | 默认可重试 |
|-------|------|------|------------|
| `user` | 参数、格式、加密、超限、额度不足等 | **文件类 user 错误释放预占不扣费**；额度不足等未预占则无回滚 | 否 |
| `system` | 内部异常、上游 5xx、未知失败 | 回退 | 是（受次数限制） |
| `timeout` | 处理超时被 kill | 回退 | 是（受次数限制） |
| `safety` | 内容安全拒绝 | 不回退 | 否 |

#### 错误码分段

| 段 | 含义 |
|----|------|
| 0 | 成功 |
| 40xxx | 用户/业务错误（`user`） |
| 41xxx | 鉴权 |
| 42xxx | 内容安全（`safety`） |
| 50xxx | 系统错误（`system`） |
| 52xxx | 上游失败（`system`） |
| 53xxx | 超时（`timeout`） |

示例：

| code | message | user_msg 示例 |
|------|---------|----------------|
| 40001 | param_invalid | 参数有误，请检查后重试 |
| 40002 | file_too_large | 文件过大，请压缩后再上传 |
| 40003 | quota_exhausted | 今日额度已用完，明天再来或开通会员 |
| 40004 | pdf_encrypted | 含加密 PDF，请先解除保护 |
| 40005 | too_many_inflight_tasks | 进行中的任务已满（最多3个），请先到任务中心查看 |
| 40007 | idempotency_key_conflict | 重复提交的内容与首次不一致，请勿复用同一幂等键 |
| 40029 | rate_limited | 请求过于频繁，请稍后再试 |
| 42001 | content_blocked | 内容未通过安全审核，请修改后重试 |
| 50001 | internal_error | 服务繁忙，请稍后重试 |
| 50002 | queue_wait_timeout | 排队超时，额度已返还，请稍后重试 |
| 53001 | task_timeout | 处理超时，额度已返还，请稍后重试 |

#### 前端安全红线

- **禁止**把堆栈、stderr、Python/Node traceback、COS 内部 XML 展示给用户  
- 开发环境可在日志面板看 `requestId`；正式版仅 `user_msg` + 可选「复制错误码」  
- Worker / API 日志可留详细错误，与 `user_msg` 分离

错误码表权威源：`packages/oc_shared/error_codes.py`（与 `docs/03-API契约.md`、开发规范 §5.4 同步）。

### 4.11 API 面（概要）

```
POST   /v1/auth/wx-login
POST   /v1/auth/refresh                # refreshToken 换发 access
GET    /v1/me
GET    /v1/me/quota

POST   /v1/uploads/credential          # 含 taskType 额度预校验；凭证 ≤15min；前缀授权
POST   /v1/tasks                       # Idempotency-Key；创建成功即预扣
GET    /v1/tasks                       # cursor 分页
GET    /v1/tasks/:id                   # 对外推荐 public_id
GET    /v1/tasks/:id/download          # 签名临时下载 URL，≤15min
POST   /v1/tasks/:id/retry             # 新 Idempotency-Key；再次预扣
POST   /v1/tasks/:id/cancel            # 成功取消则返还预扣

POST   /v1/ai/character-card/generate  # Idempotency-Key；文本输入 ≤2000 字
POST   /v1/ai/ppt/outline
POST   /v1/ai/ppt/generate             # outline 版本号 + Idempotency-Key
POST   /v1/ai/novel/outline
POST   /v1/ai/novel/chapter            # max tokens + Idempotency-Key
```

#### 创建任务与幂等键（`POST /v1/tasks`）

| 项 | 约定 |
|----|------|
| 请求头 | **`Idempotency-Key: <client-uuid>` 必填**（建议 UUIDv4）；另透传/生成 `X-Request-Id` |
| 作用域 | `(user_id, idempotency_key)` 唯一；窗口 **24h** |
| 首次请求 | 校验通过 → 落库 task → **预扣额度** → 入队 → 返回 `201` + 任务详情（含 `public_id`、`status`、`cost_quota`、`timeout` 提示） |
| 重复请求（同 Key、同请求体指纹） | **不新建、不重复扣费**；返回与首次成功时**相同业务结果**（建议 HTTP `200`，body 仍为该 task；或 `201` 但 `Idempotent-Replayed: true` 响应头） |
| 同 Key、不同请求体 | `40007`，`user_msg` 提示勿复用 Key；**不改动**原任务 |
| 请求体指纹 | 对规范化后的 JSON（type、参数、input object keys 等）做 sha256，存于幂等记录或 `tasks` 扩展字段 |
| 客户端职责 | 一次「用户点击提交」生成一个 Key；网络重试复用同一 Key；新一次提交换新 Key |
| 与并发上限 | 幂等命中已有进行中任务时，**不**因「再算一条 inflight」而拒绝；直接返回原任务 |

创建成功响应 `data` 最小字段建议：`taskId`（public_id）、`status`、`costQuota`、`timeoutAt`、`progress`。

### 4.12 Worker 稳定性与水平扩展

#### 稳定性约束

| 项 | 要求 |
|----|------|
| 进程隔离 | 每个任务在**独立子进程**（Celery prefork / 显式 subprocess）中执行，崩溃不拖垮父消费循环 |
| 资源限制 | 单任务内存上限（建议 1–2GB，按类型配置）、CPU 时间软限制；超限视为 `system`/`timeout` |
| 超时 kill | 使用 §4.3 分类型阈值；到期 **SIGKILL**；回写 `53001` 并返还额度 |
| 健康检查 | Worker 暴露 `/healthz`（进程活着 + 能连 Redis/DB/COS 配置）；编排层存活探针 |
| 死信队列 | 超过系统自动重试仍失败 → DLQ；指标 `worker_dlq_depth`；告警并支持人工重放 |
| 命令安全 | 外部二进制参数列表传入，禁止 shell 拼接用户文件名 |

#### 水平扩展策略（无状态 Worker）

| 项 | 约定 |
|----|------|
| 无状态 | Worker **不保存本地会话**；输入输出均在 COS/DB；任意副本可消费任意消息（同队列内） |
| 伸缩依据 | 优先看 `queue_depth`、`queue_age_p95`、`task_p95_duration`；深度或年龄超阈 → **加副本** |
| 伸缩方式 | K8s HPA / 云厂商弹性 / docker compose 副本数；Celery 多 worker 进程挂同一 Redis broker |
| 队列划分（建议） | `q.tools`（压缩/合并/转 PDF）与 `q.ai`（角色卡/PPT/小说）分开，避免 AI 堵死工具 |
| 缩容安全 | 先停接新消息（cancel consumer / scale 前 `warmup`），等待 inflight 完成或超时收口后再杀 pod |
| 亲和与二进制 | 工具 Worker 镜像含 Ghostscript；AI Worker 可不含 LibreOffice，按队列路由部署，降低镜像体积 |
| 上限 | 设最大副本数与单集群并发任务上限，防止打爆 COS/DB/下游模型限流 |

扩展不改变状态机与 API 契约：多 Worker 仅提高消费并行度。

### 4.13 可观测性与告警

#### 全链路 ID

- 每个请求生成 `request_id`；创建任务后所有日志/指标/**队列消息**/AI 调用必须带 `task_id`
- 小程序轮询与错误反馈展示 `requestId`（或末 8 位），便于客服排查
- 禁止出现「有失败无 task_id」的处理路径（除纯鉴权/配额查询）

#### 必监指标清单

| 指标 | 告警建议 |
|------|----------|
| `task_success_rate{type}` | 15min 窗 < 95% |
| `task_fail_rate{type,error_class}` | system/timeout 突增 |
| `task_p95_duration{type}` | 超 SLO（如合并 >60s@20MB） |
| `queue_depth` / `queue_age_p95` | 堆积或过老 |
| `worker_dlq_depth` | > 0 持续 5min |
| `worker_kill_timeout_total` | 突增 |
| `upload_orphan_cleanup_total` | 仅观测 |
| `quota_refund_total` / `quota_consume_total` | 对账异常 |
| `ai_call_fail_rate` / `ai_token_used` | 失败率与成本 |
| `api_5xx_rate` | > 1% |
| `inflight_tasks_per_user` 分布 | 触达上限比例 |

## 5. 安全、合规与风控

| 项 | 策略 |
|----|------|
| 鉴权 | 微信登录换 session；API Bearer/自定义 header |
| 上传 | 类型白名单 + 大小限制 + 魔数校验（Worker 侧再验） |
| 下载 | 带过期签名 URL，禁止永久公开桶 |
| 限流 | 用户级 QPS + 日任务上限 + 进行中任务上限 |
| 内容 | **AI 输入与输出双向审核**（文本；图片出图后审） |
| 隐私 | 输入/输出分 TTL；设置页「删除我的文件」；隐私政策说明存储时长与用途 |
| 协议 | 用户协议、隐私政策、生成内容免责声明 |
| 小程序类目 | 工具类为主；含 AI 生成须匹配「文娱-资讯/创作」等允许类目，**上架前确认类目与资质**，避免「多功能聚合」触发拒审 |
| 类目风险缓解 | 首页文案偏「文档工具」；AI 入口二级页；审核版可开关 AI 模块；准备软件著作权/主体资质 |

### 5.1 隐私说明要点（需写入《隐私政策》）

- 收集：微信 openid、上传文件、创作文本、设备与日志字段  
- 用途：文件处理、生成结果、安全审核、防滥用  
- 保存：任务元数据与操作日志长期；**输入文件默认 6h、输出文件默认 24h 删除**（见 §4.8）  
- 第三方：云厂商存储与内容安全、大模型服务商  
- 用户权利：查阅任务、删除文件、注销说明  

### 5.2 AI 双向审核

```
用户输入 → 审核 → 通过才调模型
模型输出 → 审核 → 通过才落库/出图/可下载
任一拒绝 → error_class=safety，不回退或按产品定（默认不回退防刷审）
```

## 6. 里程碑与交付物

> **总工期目标：8–10 周**（含联调与测试缓冲）。  
> 调整依据：M1 工具面大、需加测试；M2 按复杂度拆成角色卡 → PPT；M3 支付后置为可选。

### 6.1 总览表

| 里程碑 | 周期 | 累计周（参考） | 目标摘要 | 完成标准（DoD） | 关键交付物 |
|--------|------|----------------|----------|-----------------|-----------|
| **M0 基建** | **1 周** | 第 1 周 | 工程骨架、登录、空任务链路 | ① 本地一键起服可演示 ② 冒烟用例通过 ③ 脚手架/环境文档齐全 | docker-compose、OpenAPI、空 Celery 任务、错误码初表 |
| **M1 MVP 工具** | **3–4 周** | 第 2–5 周 | 转 PDF / 压缩 / 合并 + 任务中心 + 额度 | ① 三条工具可演示 ② **功能+压测通过**（见下） ③ 接口与已知问题文档齐全 | 体验版、压测报告、监控告警、PPT POC Go/No-Go |

**周次编排（推荐 9 周中位，可在 8–10 内伸缩）：**

```
W1        M0
W2–W5     M1（其中末 1 周侧重回归/压测；若赶工可压成 3 周）
W5.5–W7   M2a（可与 M1 收尾少量重叠，但不抢 M1 测试人力）
W7–W9     M2b（仅 POC=Go；否则跳过并进入 M3）
W9–W10    M3 小说；支付/会员 = 可选加时或 V1.1
```

若整体只拿 **8 周**：M1=3 周、M2a=1.5、M2b=1.5、M3=1（支付必可选跳过）。  
若拿满 **10 周**：M1=4 周（加缓冲测试）、M2a=2、M2b=2、M3=1。

### 6.2 分阶段说明

- **加长原因**：工具组合多 + 失败分类/额度/压测，**最后不少于 1 周**做回归与压测，禁止「功能刚通就开 M2」

| 完成标准 | 具体含义 |

#### M2a — 角色卡（1.5–2 周）

- 生成 → **本地编辑确认** → 出图保存；输入/输出双向审核；差异化扣点

| 完成标准 | 具体含义 |

| 测试通过 | 额度预扣/安全拒绝不返还/版本冲突（乐观锁）等核心用例通过 |

#### M2b — PPT（1.5–2 周，**依赖 M1 POC=Go**）

- 大纲强制二次编辑 → 模板填充 → pptx 下载（1–2 套模板即可）
- POC=No-Go：本里程碑 **取消或降级为「仅大纲导出」**，工期释放给 M3/打磨；变更记入已知问题与 §1.4

| 完成标准 | 具体含义 |

#### M3 — 小说与收口（1–1.5 周；**支付可选**）

- **必须**：小说设定→大纲→分章/续写→TXT 导出；token/章节上限；双向审核

| 文档齐全 | 小说 Prompt/限制说明、上架检查清单；**支付若未做，在验收单标注「可选未交付」即可通过 M3** |

### 6.3 阶段门禁（Gate）

| Gate | 时机 | 不过则 |
|------|------|--------|
| G0 | M0 结束 | 不得开始 M1 业务开发 |
| G1 | M1 结束（含压测） | 不得开始 M2a；工具体验版不提审 |
| G2a | M2a 结束 | 可并行筹备 M2b；角色卡可进体验版 |

每阶段通用交付件：**可演示包 + 接口/变更说明 + 已知问题清单 + 完成标准勾选表**。

## 7. 环境与部署

| 环境 | 用途 |
|------|------|
| local | `docker-compose` + 微信开发者工具 |
| dev | 联调、体验版小程序 |
| staging | 预发、审核前验证 |
| prod | 正式版 |

部署原则：

- API 与 Worker 分离扩缩容；Worker **无状态**，按队列深度自动加副本（§4.12）
- 工具队列与 AI 队列可分池部署（镜像与限流不同）
- Worker 镜像按角色含 Ghostscript /（可选）LibreOffice
- 密钥仅存环境变量/密钥管理，禁止入库进仓
- 编排探针依赖 Worker `/healthz`

## 8. 风险清单

| 风险 | 影响 | 缓解 |
|------|------|------|
| Office 转换不稳定 | 转化失败 | 格式白名单、重试、明确 `user_msg`；V1 可砍 F07 |
| 大文件超时 | 体验差 | 收紧合并边界、异步、timeout 回退额度 |
| AI 成本飙升 | 亏损 | 差异化扣点、章节 token 上限、大纲确认 |
| **微信类目/AI 审核** | 上架受阻 | 类目预审、AI 开关、双向内容安全、资质 |
| 版权投诉 | 运营风险 | 协议 + 举报入口 + 操作日志 |
| Worker 内存打爆 | 雪崩 | 进程隔离、单任务限额、DLQ |
| 孤立上传堆积 | 成本 | **6h** 清理 + 指标 |
| PPT 模板不可用 | M2b 延期或跳过 | M0 启动 POC，M1 末 Go/No-Go 门禁 |
| M1 测试不足 | 线上工具事故 | M1 固定 3–4 周且末周压测；G1 门禁 |
| 支付排期挤占小说 | M3 完不成 | 支付标为可选，不阻塞验收与提审 |
