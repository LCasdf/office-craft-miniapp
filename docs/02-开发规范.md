> 文档版本：v0.7  
> 更新日期：2026-09-07  
> 适用范围：`apps/miniapp`、`apps/api`、`apps/worker`、`packages/oc_shared`、`packages/oc_core`  
> 对齐进度：`docs/07-项目进度.md`  
> 变更摘要：download/retry 已落地；CI 覆盖率地板 60%（G1 目标行 80%/分支 70% 不变）

---

## 1. 总则

1. **可读性优先于炫技**：优先清晰命名与小函数，避免过度抽象。
2. **改动最小化**：只改任务相关文件；禁止顺手大重构。
3. **契约先行**：前后端/Worker 变更先改 `packages/oc_shared` 与接口文档（OpenAPI）。
4. **异步任务强制**：凡满足任一条件必须走 **Celery** 入队，**禁止在 HTTP 请求内同步阻塞**：
   - 预估耗时 **> 1s**
   - 涉及文件 IO（下载/上传/加解码）
   - 调用外部命令（Ghostscript、LibreOffice 等）
   - 调用 AI / 长耗时上游 HTTP
5. **密钥零入库**：任何密钥、Token、COS Key 不得提交 Git。
6. **中文产品文案，英文代码标识**：用户可见文案用中文；代码、提交、分支用英文。
7. **后端栈已锁定**：Python 3.11+ / FastAPI + Celery + Redis（见 ADR-0001）；勿再引入第二套后端运行时。

## 2. 目录与模块边界

### 2.1 职责边界

| 包/应用 | 允许做 | 禁止做 |
|---------|--------|--------|
| `miniapp` | UI、鉴权态、上传、轮询任务 | 直接调云厂商密钥、跑文件转换；**禁止在客户端代码中硬编码或存储 COS 临时密钥/永久密钥，必须通过 API 获取上传凭证** |
| `api` | 鉴权、**额度变更**、建任务、签 URL、调 AI 网关、入队 | 执行 Ghostscript/LibreOffice |
| `worker` | 消费队列、文件处理、出图、**仅回写 Task/Asset 状态与产物** | 修改 `quotas`/`users`；对用户暴露业务 HTTP（除健康检查） |
| `oc_shared` | 枚举、DTO、错误码、user_msg、跨端常量 | 业务副作用、I/O、DB 会话 |
| `oc_core` | SQLAlchemy 模型、领域服务 | 被 miniapp 依赖；在 worker 中调用「改额度」API；**禁止 import fastapi / celery 等框架模块，保持纯领域逻辑** |

### 2.2 依赖方向

```
miniapp    →（HTTP / OpenAPI / 生成的 TS 类型）
api        → oc_shared, oc_core
worker     → oc_shared, oc_core
oc_core    → oc_shared

禁止：apps 业务包互相 import（api ↛ worker，worker ↛ api）
禁止：miniapp 引用 Python 包源码
禁止：api 在请求路径直接调用 gs/soffice
禁止：worker 调用配额扣减/回滚服务（即使函数在 oc_core 也禁止从 worker 入口触发）
```

### 2.3 Monorepo 工程约束

1. 修改 `oc_shared` 中的枚举 / DTO / 错误码，**必须同步**：
   - `apps/api` 校验与路由
   - `apps/worker` 消息消费与分支
   - `apps/miniapp` 常量 / 生成类型 / 文案映射
2. `oc_shared` 任意破坏性改动必须跑 **全链路回归**（至少：创建任务、额度、一轮工具任务、OpenAPI 生成物更新）。
3. **`apps/*` 禁止互相 import**；共享逻辑下沉到 `oc_shared` / `oc_core`。
4. Pydantic 模型变更后须 **导出/生成 TypeScript 类型** 供小程序使用（推荐：FastAPI OpenAPI → `openapi-typescript` 或等价流水线）；禁止长期手写漂移副本而不校验。
5. PR 若只改 `oc_shared` 未更新消费方，评审直接打回。

## 3. 命名规范

### 3.1 通用

| 类型 | 风格 | 示例 |
|------|------|------|
| Python 模块/文件 | snake_case | `task_service.py` |
| Python 函数/变量 | snake_case | `create_task` |
| Python 类 | PascalCase | `TaskStatus` |
| 小程序文件/目录 | kebab-case | `task-service.ts` |
| 小程序函数/变量 | camelCase | `createTask` |
| 小程序/共享类型名 | PascalCase | `TaskStatus` |
| 常量 | UPPER_SNAKE | `MAX_PDF_SIZE_MB`（放置见 §3.4） |
| DB 表（实体） | snake_case 复数 | `tasks`、`users`、`assets` |
| DB 表（关联/从属） | `{主体}_{从属}`，snake_case | `task_assets`、`user_quotas`；主体在前、从属在后 |
| DB 字段 | snake_case | `created_at` |
| COS Key | `{env}/{userId}/{uploadId|taskId}/{safe_name}` | 见 §6.6 |
| Celery 任务名 | 点分模块路径 | `oc_worker.tasks.pdf.merge_pdf` |

> 关联表说明：多对多或「从属于某主体的扩展/关系」优先用 `{主体}_{从属}`（如任务与文件关系 → `task_assets`，用户额度账户 → `user_quotas`）。已有短名表（如落地 DDL 中的 `assets`、`quotas`）以数据模型文档为准，**新增表**须遵守本约定。

### 3.2 任务类型枚举（统一）

权威定义在 `packages/oc_shared`（Python Enum / Literal）。小程序侧使用生成类型或同步枚举：

```ts
enum TaskType {
  ImageToPdf = 'image_to_pdf',
  PdfCompress = 'pdf_compress',
  PdfMerge = 'pdf_merge',
  OfficeToPdf = 'office_to_pdf',
  PptGenerate = 'ppt_generate',
  NovelChapter = 'novel_chapter',
  CharacterCard = 'character_card',
}
```

新增类型必须同步：`oc_shared`、API 校验、Celery 路由与队列、小程序文案（见 §2.3）。

### 3.3 小程序页面路径

```

pages/tools/pdf-merge/index

pages/create/ppt/index
```

### 3.4 常量放置位置

| 范围 | 放置位置 | 说明 |
|------|----------|------|
| Python **全局/跨端**常量 | `packages/oc_shared/constants.py`（或 `oc_shared/constants/` 包） | 错误码段、任务类型相关上限、与契约共用的魔法数；禁止在 api/worker 各写一份 |
| Python **业务模块**常量 | 对应模块下的 `constants.py` | 如 `apps/api/.../constants.py`、`apps/worker/.../constants.py`；仅本模块使用 |
| 小程序 **全局**常量 | `apps/miniapp/miniprogram/constants/` | 按域拆分文件（如 `task.ts`、`error-codes.ts`）；页面内禁止散落重复魔法数 |

原则：能进 `oc_shared` 的跨进程常量优先进共享包；改共享常量须遵守 §2.3 全链路同步。

## 4. TypeScript 与数据访问规范

### 4.1 TypeScript 规范

1. 开启 `strict`；禁止无必要的 `any`（确需时写注释原因）。
2. 公共函数必须有明确入参/出参类型；跨端 DTO 以 `oc_shared` + OpenAPI 生成物为准。
3. 优先 `unknown` + 收窄，而非 `any`。
4. 禁止默认导出业务类（`export class` 用命名导出），小程序页面入口除外。
5. 日期在 API 层统一 **ISO 8601 字符串**；MySQL 用 `DATETIME(3)`。
6. 金额/额度用整数（分/次数），禁止浮点金额。

### 4.2 Python 规范（摘要）

1. FastAPI / Worker 使用 Python 3.11+；类型注解完整，Pydantic v2 做边界校验。
2. 公共异常转为契约错误码 + `user_msg`，禁止把 traceback 返回客户端。
3. 外部 HTTP 客户端（httpx 等）**必须**设置 connect/read 超时。

### 4.3 DB 编码约束

1. **任务创建与额度预占/扣减必须在同一数据库事务中完成原子提交**，防止「有任务无预占」或「有预占无任务」。
2. `task` 状态进入可计费态时，`cost_quota`、`quota_settled` 的写入与额度行更新须在**同一事务**。
3. 成功终态：API 侧（或由 API 提供的短事务回调/outbox 消费者）将预占**转正扣**；禁止拆成无锁的多步裸更新。
4. **禁止 Worker 开启长数据库事务**（尤其不要在跑 gs/soffice/下载上传期间持有事务）。
5. Worker **仅允许**操作与当前任务相关的 `tasks`、`assets`（及只读关联的 `storage_objects` 引用计数等文件元数据）；**禁止修改 `users`、`quotas`**。
6. 额度变更（预占、转正、回滚）**只允许 `apps/api` 进程内服务执行**（含定时补偿扫描若需改额度也挂在 api/补偿服务，不进 worker 业务任务）。

## 5. API 规范

### 5.1 URL 与版本

- 前缀：`/v1`
- 资源名词复数：`/v1/tasks`
- 动作用子路径：`/v1/tasks/:id/retry`、`/v1/tasks/:id/download`

### 5.2 鉴权方式

1. **登录下发双 Token**（`POST /v1/auth/wx-login`）：
   - `accessToken`：短期访问令牌，默认有效期 **2 小时**；
   - `refreshToken`：刷新令牌，默认有效期 **30 天**；
   - 具体秒数放配置（`ACCESS_TOKEN_TTL` / `REFRESH_TOKEN_TTL`），禁止散落硬编码。
2. **小程序存储**：
   - `accessToken`（及过期时间）存本地，请求头携带：`Authorization: Bearer <accessToken>`；
   - `refreshToken` 仅存安全存储，**禁止**写入日志、分享卡片或代码常量；
   - **禁止**在客户端存 COS 密钥（见 §2.1）。
3. **刷新流程**：
   - access 过期或收到鉴权失败且仍持有未过期 refresh → 调用 `POST /v1/auth/refresh`（参数按契约）；
   - 刷新成功后更新本地双 Token，**用新 access 重试原请求一次**；
   - 刷新失败（过期/吊销）→ 清空会话 → 走微信登录。
4. **401 / `41001` 处理策略**（与 §7.3 一致）：
   - 统一在 `request` 封装内处理，页面不各自实现；
   - **禁止**并发请求各自刷新导致风暴：全局单飞（mutex/queue），共用同一次 refresh；
   - **禁止** refresh 失败后死循环重试登录接口。
5. 除登录、刷新外，业务 API 均需有效 access；管理端鉴权另议，不与小程序 token 混用。

### 5.3 响应包络

成功：

```json
{ "code": 0, "message": "ok", "user_msg": "ok", "data": {}, "requestId": "req_xxx" }
```

失败：

```json
{ "code": 40003, "message": "quota_exhausted", "user_msg": "今日额度已用完，明天再来或开通会员", "data": null, "requestId": "req_xxx" }
```

前端默认只展示 `user_msg`；禁止返回堆栈。

### 5.4 错误码分段与维护

| 段 | 含义 |
|----|------|
| 0 | 成功 |
| 40xxx | 客户端/业务可预期错误（参数、额度、权限、**限流**） |
| 41xxx | 鉴权失败 |
| 42xxx | 内容安全拒绝 |
| 50xxx | 服务端内部错误 |
| 52xxx | 上游（AI/存储）失败 |
| 53xxx | 超时 |

**维护约定（强制）：**

1. 错误码权威源：`packages/oc_shared/error_codes.py`。
2. 使用 **枚举（或等价常量结构）** 定义每一项，至少包含：
   - `code`：int（如 `40003`）
   - `message`：机器可读 snake_case（如 `quota_exhausted`）
   - `user_msg` / 中文文案：用户可见说明
   - `http_status`：建议 HTTP 状态码（如限流 **429**、鉴权 **401**、成功 **200**）
3. 小程序端由脚本 **生成对应常量文件**（如 `constants/error-codes.ts`），禁止长期手写漂移；改枚举须走 §2.3 全链路同步。
4. 明细与示例见 `docs/03-API契约.md`；新增码必须先改 `error_codes.py` 再改契约。

限流示例码：`40029` / `rate_limited` / HTTP `429` / `user_msg`：「请求过于频繁，请稍后再试」。

### 5.5 限流

| 接口类 | 默认限额（按用户） | 实现位置 |
|--------|-------------------|----------|
| 任务创建（`POST /v1/tasks`、等价扣费创建/重试） | **1 次/秒** | API 网关或 FastAPI 中间件（Redis 滑动窗口/令牌桶） |
| 任务列表（`GET /v1/tasks`） | **5 次/秒** | 同上 |
| 其他读接口 | 可配置，建议不低于列表 | 同上 |

1. 超限返回业务包络：`code=40029`（归入 **40xxx**），HTTP 状态码 **429**，`Retry-After` 可选。
2. 限流键建议：`user_id + route`；未登录仅登录接口按 IP 限制（防刷）。
3. 限流在鉴权之后、重业务之前；与「进行中任务 ≤3」并发上限互补，不互相替代。

### 5.6 分页

```
GET /v1/tasks?cursor=xxx&limit=20
```

返回：`{ items, nextCursor, hasMore }`。禁止深翻页大 offset。

### 5.7 幂等

1. 创建类扣费接口 **`Idempotency-Key` 必填**；同一用户同一 Key 24h 内返回同一业务结果，不重复预占。
2. **小程序生成方式（强制）：**
   - 用户每次点击「提交」调用 `utils/idempotency.ts`（或等价）生成 **UUIDv4**；
   - 写入本次提交的内存/页面 data，**网络重试、防抖重复点击复用同一 Key**；
   - 用户修改参数后再次主动提交 → **必须换新 Key**；
   - Key 禁止用时间戳截断或任务标题等可猜测值。
3. 同 Key 不同请求体 → `40007`，不覆盖原任务。

### 5.8 额度 / 扣费编码强制约束

1. **禁止「处理完成后再扣费」**。任务创建成功路径必须：**先预占额度 → 再落任务/入队**。
2. 结算规则（编码必须遵守）：
   - **成功**：预占 **转正扣**（`quota_settled=1`）；
   - **系统失败 / 超时 / 用户取消**：回滚释放预占（不扣费）；
   - **用户自身文件错误**（加密 PDF、损坏、类型不符等 `error_class=user` 且属输入文件问题）：**释放预占、不扣费**；
   - **内容安全拒绝（`safety`）**：默认不返还（防刷审）；若产品改口须改契约 + 本条并出 ADR。
3. 预占、转正、回滚必须使用 **数据库事务 + 行级锁/条件更新**（如 `SELECT ... FOR UPDATE` 额度行），防止并发超扣。
4. **额度变更只允许 API 服务执行**；Worker **禁止**直接改 `quotas` / `users`，仅回写 `tasks`（及 `assets`）状态与结果元数据。
5. Worker 在失败终态写入 `error_class` 后，由 API 补偿任务或「状态变更 outbox → API 消费者」触发回滚/转正；**不得**在 worker 内直接 `UPDATE quotas`。

### 5.9 下载接口

1. **推荐（已实现）：** `GET /v1/tasks/{taskId}/download`
   - 鉴权 + **校验任务归属 `user_id`**；
   - 仅 `status=succeeded` 且未过期可下载；过期返回 `40016`；
   - 响应 `data` 返回 **带签名的临时下载 URL**，默认有效期 **15 分钟**（可配置，≤15min 为宜）；
   - 可选同时返回 `filename`、`expireAt`、`sizeBytes`。
2. **亦可：** 任务详情中的 `outputs[].downloadUrl` 使用同等签名策略（15 分钟）；过期后详情 `outputs=[]` / `resultExpired=true`，须重新拉详情或调 download 刷新。
3. **禁止：** 永久公开桶、把无过期直链写进可分享二维码长期传播；禁止返回 COS 永久密钥。
4. 契约细节见 `docs/03-API契约.md` §4.6。

## 6. 任务与文件规范

### 6.1 创建任务流程

1. 小程序生成 `Idempotency-Key` → 调用 **`POST /v1/uploads/credential`** 申请上传凭证：
   - 凭证有效期 **≤ 15 分钟**；
   - STS/预签名 **仅授权到指定 COS key 前缀**（如 `{env}/{userId}/uploads/{uploadId}/`），禁止桶级过宽权限；
   - 附带 `taskType` 做额度预校验（余额不足拒发凭证）。
2. 直传 COS（key 经清洗，且必须落在凭证前缀内）
3. `POST /v1/tasks`（object keys + 参数 + 幂等键）
4. API：**事务内**校验归属/并发上限/额度预占 → 写 task → 入队
5. Worker 处理 → **仅**回写 task/asset 进度与终态
6. API 侧根据终态转正或回滚额度
7. 小程序用**指数退避轮询**；杀进程后回任务中心拉结果；下载走 §5.9

### 6.2 任务状态机

与蓝图 §4.3 对齐。`tasks.status` 仅允许下列枚举（`oc_shared` 定义，大小写与字符串一致）：

| 状态 | 含义 |
|------|------|
| `pending` | 已创建、尚未入队或入队瞬间 |
| `queued` | 已在队列等待消费 |
| `running` | Worker 已开始处理 |
| `succeeded` | 成功终态 |
| `failed` | 失败终态（含 timeout；细分看 `error_class`） |
| `cancelled` | 用户取消终态 |

流转摘要：`pending → queued → running → succeeded | failed`；任意非终态可 → `cancelled`（规则见 API）；`failed` 且可重试时经 API → 再次 `queued`。
**禁止**用未文档化的自定义 status 字符串；展示「过期」用 `result_expired` 标志，不新增 `expired` 状态（与蓝图一致）。

### 6.3 进度约定

`progress`：0–100 整数，**仅用于 UI 展示**。建议节点：

- 10 入队成功
- 30 下载输入完成
- 60 处理中
- 90 上传结果完成
- 100 成功（可与 `status=succeeded` 同时出现）

**强制：**

- **`task.status` 才是任务真实状态**；业务逻辑（是否可下载、是否重试、是否计费、是否取消）**禁止**依赖 `progress` 数值判断结果。
- 例如禁止：`if progress == 100` 当成功；必须以 `status == succeeded`。

### 6.4 文件限制与任务超时

| 场景 | 限制 |
|------|------|
| 单文件 | ≤ 50MB（按类型可更严） |
| 合并总大小 | ≤ 50MB |
| 合并文件数 | 2–10 |
| 图片转 PDF 张数 | ≤ 20 |
| 输入 TTL | **6h**（见 §6.6） |
| 输出 TTL | **24h** |
| **任务超时（默认）** | **180s**；**可按 `taskType` 在配置中覆盖**（见下） |

**任务超时（强制配置化）：**

1. **默认 180s**；各类型覆盖值与蓝图 §4.3 对齐（如压缩 60s、合并 120s、AI 120s），写在 `configs/task_timeouts.yaml`（或等价）。
2. API 写入 `timeout_at`、Celery `time_limit` / 软限制读取**同一配置源**。
3. **禁止**在业务代码中硬编码魔法秒数（测试除外可用常量夹具）。

### 6.5 Worker 编码要求（含 Celery）

1. 入口只认队列消息，消息 schema 版本化：`schemaVersion`。
2. 处理函数必须 `try/finally`，保证失败回写 `failed` + `error_code` / `error_class`。
3. 临时目录用完即删；容器内禁止堆积 `/tmp`。
4. 外部命令（gs、soffice）必须：参数列表传入（防注入）、超时杀死、采集 stderr（仅进 `error_detail`）。
5. 不在日志打印用户文件内容或完整 URL 签名 query。
6. **全局任务超时**：Worker/Celery 必须配置硬限制（如 `task_time_limit`，可与类型配置取 min）；超时后进程被杀，任务回写 **`failed` + `error_class=timeout`**（`53001`），再由 API 侧回滚预占。
7. **Celery 幂等**：消费逻辑以业务 `taskId` 去重；重复投递检测到终态则直接 ACK，禁止重复处理副作用。
8. **Celery 自动重试**：若启用，**必须幂等**，且 **不得超过 2 次**；重试**不得再次扣减/预占额度**（额度仅在 API 创建/用户主动 retry 时处理）。超时与超限重试进入 **DLQ**，禁止无限重试。
9. **用户侧重试**：最大 **2** 次；`tasks.retry_count` **持久化**，经 API 校验后重新预占再入队。
10. **所有外部 HTTP 调用强制设置超时**（AI、内容安全、COS SDK 等效超时）。
11. **按类型隔离队列**：至少 `q.tools` 与 `q.ai` 分开；路由在 `task_routes` 配置。

### 6.6 文件生命周期编码约束

1. **TTL**：输入对象 **6h**；输出对象 **24h**。COS 生命周期规则 + **内部定时清理任务**双重兜底。
2. 清理「已发凭证 / 已上传但 **未成功创建 task**」的孤立 COS 前缀（对齐上传 `uploadId`）；凭证本身 15 分钟过期，对象清理窗口按 6h TTL。
3. 任务成功或确定失败后，业务代码应 **主动删除** 不再需要的输入（及过期输出）；**禁止只依赖 TTL** 作为唯一清理手段。
4. **COS key 安全**：
   - 禁止把用户原始文件名直接拼进 key 路径；
   - 仅允许安全字符集，剥离 `../`、`\`、空字节等；
   - 原始名可存 `assets.original_filename`，对象键使用 `{uploadId}/{index}_{short_hash}.ext` 等形式，**防止路径穿越**；
   - 直传必须落在凭证签发的 **前缀** 内，建任务时校验 key 前缀与用户归属。

## 7. 小程序前端规范

### 7.1 结构

```
apps/miniapp/
  miniprogram/
    pages/
    components/        # 公共组件（功能命名）
    services/          # API 封装（唯一网络出口）
    stores/            # 全局状态
    utils/             # 含 idempotency、pollBackoff、cache
    constants/
    styles/
```

### 7.2 状态管理

1. **全局状态**（用户信息、登录态、额度摘要等）使用 **mobx-miniprogram** 或自研轻量 store，统一放在 `stores/`。
2. **禁止**通过页面路由参数、`getCurrentPages` 互相塞 **大对象**（整份任务列表、大段小说正文、文件二进制等）；跨页只传 id，数据回 store 或重新请求。
3. **页面局部状态**（表单草稿、上传进度 UI、开关）使用页面实例的 `this.setData`，不要强行塞进全局 store。
4. store 更新后需要驱动视图时，优先用观察绑定；避免在多处手写重复 `setData` 拷贝同一全局字段。
5. 额度等关键数以服务端为准；store 可为展示缓存，提交前/返回前台应有刷新策略（可与 §7.7 缓存 TTL 配合）。

### 7.3 组件规范

1. 公共组件放在 `miniprogram/components/`，以 **功能** kebab-case 命名（如 `upload-area`、`task-progress`、`quota-badge`）。
2. **组件内部不直接调用 API**（不 import `services/*` 发请求）；通过：
   - **properties / props** 接收展示数据与配置；
   - **triggerEvent** 回调（如 `submit`、`retry`、`chooseFile`）由页面处理副作用。
3. 纯展示/交互组件保持可复用；带强业务的「智能组件」若必须请求，须在 CR 说明理由，且仍优先薄封装为页面编排。
4. 组件样式默认使用相对单位与 tokens；避免写死与品牌无关的全局选择器泄漏。

### 7.4 UI/交互

1. 工具页统一：上传区 → 参数区 → 主按钮 → 结果/进度。
2. 长任务必须进入「任务中心」可回看，禁止只 toast。
3. 错误文案对人话：只展示 `user_msg`。
4. 下载失败提供「复制链接」兜底。
5. 不在首屏堆砌入口：首页宫格 ≤ 8 个。
6. AI 文本输入展示剩余字数；超出 **2000 字符** 禁止提交（见 §8.4）。

### 7.5 网络

1. 统一 `request` 封装：自动带 token、`requestId`、`Idempotency-Key`（创建类）、错误码映射。
2. 遇 HTTP 401 / `code=41001`：按 §5.2 **单飞刷新** access；失败则清会话并引导登录；**禁止**死循环刷新。
3. 页面 `onHide`/`onUnload` **停止本页轮询定时器**（不影响后端任务）。
4. 下载优先调 §5.9；签名 URL 过期后刷新，不缓存超过有效期的链接当永久地址。

### 7.6 样式

1. 使用 CSS 变量定义品牌色、间距、圆角（`styles/tokens.wxss`）。
2. rpx 布局；关键点击热区 ≥ 44px。
3. 避免引入无关大型 UI 框架。

### 7.7 缓存策略

1. **可不常变数据**允许本地缓存，例如：任务类型列表、额度每日上限文案/配置、模板列表等。
2. 默认 TTL **5 分钟**；必须写入 `expireAt`（或等价），读取时校验，**过期必失效并重新请求**。
3. **禁止**缓存：access/refresh 策略另遵 §5.2；COS 签名下载 URL；用户正文长文当「永久草稿」却不标注版本（草稿可另存，但不走 5 分钟配置缓存混用）。
4. 额度余额、进行中任务数等 **高频变化** 数据：TTL 应更短或仅内存，提交前强制拉 `/v1/me/quota`。
5. 封装建议：`utils/cache.ts` 统一 `get/set/remove`，禁止各页面私自 `wx.setStorage` 无过期字段。

### 7.8 弱网与进程销毁边界

1. 小程序被系统杀后台后，**后端任务独立运行**；用户下次打开从 **任务中心拉状态/结果**，不依赖小程序进程存活。
2. 轮询采用 **指数退避**（例：2s → 4s → 8s … 上限 15–30s），成功/终态停止；**禁止**固定 2s 高频一直打。
3. 提交前前端生成 **`Idempotency-Key`**（见 §5.7），按钮防抖 + 同 Key 重试，防止重复点击双建任务。
4. 弱网超时：展示「可到任务中心查看」，不要假设请求失败即任务不存在（可能已建单）。

## 8. AI 功能规范

### 8.1 Prompt 与调用边界

1. **Prompt 与代码分离**：模板放 api 侧 `prompts/` 目录，带版本号；禁止把系统 Prompt 下发到小程序。
2. **模型调用抽象（强制）**：
   - 所有大模型调用必须经过统一的 **`AIClient`**（建议位置：`apps/api` 或 `packages/oc_core` 的 ai 适配层）；
   - **禁止**业务路由/Worker 任务直接 new 各家 SDK 散落调用；
   - `AIClient` 须支持 **多供应商切换**（配置驱动：模型名、base_url、密钥引用）；
   - 每次调用记录 **token 使用量**（prompt/completion/total）及 `provider`/`model`/`requestId`/`taskId`，写入日志与统计表（或 `ai_sessions` 累计字段），用于成本核算；
   - 超时、熔断、不可用时走 §11.5 降级，由 `AIClient` 统一抛出可映射错误码。

### 8.2 输出优先结构化

1. 角色卡 / PPT 大纲等必须按 **JSON Schema** 校验。
2. 校验失败允许模型侧重试，**最多 2 次**；重试时可在 prompt 中 **附带上次 Schema/解析错误信息**（截断后），引导模型修正输出。
3. **2 次重试后仍失败**：任务（或同步接口）标记 **`failed`**，`error_class=system`（或约定的结构化失败码），按 §5.8 回滚预占；**禁止**把非法 JSON 当成功返回前端。
4. 校验与重试逻辑放在 `AIClient` 或紧邻的结构化输出管道，避免每个业务复制粘贴。

### 8.3 审核、计费与降级

1. **审核**：输入与输出双向内容安全；不通过返回 `42xxx`。
2. **计费**：创建/触发生成时 **预占**（§5.8）；成功转正；禁止「下载时再扣」的隐式逻辑。大纲预览是否免费按产品配置。
3. **禁止**：系统 Prompt、密钥、完整用户长文进客户端日志。
4. 小说须大纲确认后再写章；遵守 max tokens（蓝图 §3.3 / §4.3）。
5. AI 上游不可用时走 §11.5，**不要**把必失败任务堆进队列。

### 8.4 用户输入长度限制

1. AI 生成类接口的文本输入（小说设定、角色卡描述/设定、PPT 主题与补充说明等）**最大长度 2000 字符**（按 Unicode 字符计，前后端约定一致）。
2. **前端**：输入框 `maxlength` + 提交前校验；超限展示明确提示，不发起请求。
3. **后端**：Pydantic/校验层 **再次校验**；超限返回 `40001` 或专用 `40013`（`input_too_long`），不得依赖前端。
4. 多字段场景：可对「设定类主文本」各限 2000，或对拼接后的审计文本设总上限——以接口契约为准，但任一用户可见大文本框不得突破 2000 而未说明。
5. 与模型 token 上限同时生效时，取更严者；超限裁剪须产品确认，默认 **拒绝** 而非静默截断。

- [ ] 有无额度/鉴权校验？创建是否校验单用户排队上限？

- [ ] 错误码能否映射到 `user_msg`？日志是否含敏感信息？
- [ ] `oc_shared` 变更是否同步 api/worker/miniapp？
- [ ] 用户生成内容展示是否避免危险 HTML 渲染（§15）？

### 9.5 CI/CD

1. **PR 合并门禁（必须通过）：**
   - Lint（ruff/eslint 等按栈配置）
   - 类型检查（Python：`mypy`/`pyright` 择一；小程序：`tsc`）
   - 单元测试
   - 构建（api/worker 镜像或包构建；小程序构建检查）
   - 依赖漏洞扫描（§15：`pip-audit`）
2. **部署策略：**

3. **版本与变更日志：**
   - 每次正式发布打 **`vX.Y.Z`** tag（SemVer）
   - 使用 **semantic-release** 自动生成，或人工维护 `CHANGELOG.md`（二选一，团队统一）；tag 与 changelog 必须对应可追溯提交
4. CI 配置入库（GitHub Actions / 等价），禁止只在本地「感觉过了」就合并。

## 11. 日志、监控与告警

### 11.1 日志库与字段

1. Python 统一使用 **`structlog`** 输出 **JSON** 日志（api/worker 同一配置）；禁止业务里 `print` 当日志。
2. 必带字段：`requestId`、`userId`（可哈希）、`taskId`、`taskType`、`level`、`message`；AI 调用附加 `provider`/`model`/token 用量。
3. 禁止：文件正文、手机号明文、完整签名 URL、密钥、系统 Prompt 全文。

### 11.2 全链路与追踪

1. **MVP 强制**：`requestId`（及任务相关的 `taskId`）在 API → 队列消息 → Worker → 下游 HTTP **全链路传递**；日志可按 `requestId` 检索完整调用。
2. **后续**：可接入 **OpenTelemetry**（trace/span）；MVP 不阻塞上线，但新增代码不要写死无法注入上下文的全局客户端。

### 11.3 指标与监控系统

1. 监控栈：**Prometheus + Grafana**（或云厂商监控等价能力，指标语义对齐）。
2. 仓库维护 **Grafana dashboard 模板**（或云监控看板导出 JSON），覆盖至少：
   - 任务成功率 / 失败率（按 type、error_class）
   - 队列深度与年龄（`q.tools` / `q.ai`）
   - P95 耗时、超时次数、DLQ 深度
   - API 4xx/5xx、限流次数
   - AI 失败率与 token 消耗
3. 指标导出：api/worker 暴露 `/metrics`（或 sidecar），命名稳定可告警。

### 11.4 告警（最低配置）

- 成功率 < 95%（15 分钟窗）
- 队列堆积 > 阈值
- Worker 连续崩溃 / DLQ 深度 > 0
- 5xx 突增、依赖扫描流水线失败（发布门禁）

### 11.5 降级策略

| 故障 | 策略 |
|------|------|
| AI 不可用 | API **直接返回业务错误**（如 `52001`），**不入队堆积**必失败任务 |
| COS 故障 | 上传凭证/下载 **直接失败**并明确 `user_msg`，不假装成功 |
| 队列过载 | API **拒绝新建任务**（繁忙码 + 文案），保护 Worker 与下游，防止雪崩 |
| 内容安全超时 | 计为系统/上游失败并按 §5.8 回滚预占（或快速失败不预占） |

降级开关应可配置，发版需验证（§17）。

## 12. 配置与密钥

1. 使用 `.env.example` 列出全部变量，无真实值；真实密钥仅存环境/密钥管理，**禁止**入库。
2. 分环境：`local` / `dev` / `staging` / `prod`。
3. **运行时配置（MVP）**：环境变量 + **Settings 类**（如 pydantic-settings）统一加载；限额、分类型超时、TTL、队列名均走 Settings/配置文件，禁止散落硬编码。
4. **后续**：可引入配置中心（如 Nacos）；引入前须保证本地/CI 仍可用 env 回退。
5. 小程序端只保留 `API_BASE_URL` 等公开配置。
6. **密钥轮换**：COS 密钥、微信 `AppSecret`、JWT 签名密钥、AI Provider Key 等 **至少每 90 天轮换一次**；轮换步骤与责任人记入 **安全手册**（`docs/security-runbook.md` 或等价），轮换后验证登录/上传/AI 冒烟。

## 13. 数据库规范

1. **表必备字段**：除非文档声明的只追加审计表，否则所有表必须有：
   - `id` 主键（`BIGINT UNSIGNED` 或契约约定的主键策略）
   - `created_at`
   - `updated_at`（只追加日志表如 `operation_logs` 可仅有 `created_at`，须在模型注释标明）
2. **索引命名**：`idx_{table}_{column}`；联合索引 `idx_{table}_{col1}_{col2}`；唯一约束 `uk_{table}_{column}`。
3. **外键**：优先在 **应用层** 维护引用完整性；数据库 `FOREIGN KEY` **可选**（按迁移与分库需求决定），有 FK 时仍须在服务层做归属校验。
4. **访问方式**：必须使用 **SQLAlchemy ORM** 或 **参数化查询**；**禁止**字符串拼接 SQL。
5. 迁移用 **Alembic**；禁止生产手工改表不留迁移。
6. 与 `docs/04-数据模型.md` 冲突时，先改数据模型文档再改代码。

## 14. 缓存规范

1. **Key 命名**：`oc:{业务}:{标识}`，例如：
   - `oc:quota:{userId}`
   - `oc:task:types`
   - `oc:ratelimit:{userId}:{route}`
2. **过期时间**：必须设置 TTL；禁止无 TTL 的「永久缓存」除非显式文档化（如极少变的功能开关且具备主动失效）。
3. **与 DB 一致性（默认策略）：**
   - **读多写少配置**：Cache-Aside + TTL（如 5 分钟，与小程序缓存策略可对齐语义）；
   - **额度/预占等强一致路径**：以 DB 事务为准，可用短 TTL 缓存展示；**写后失效（delete/invalidate）** 对应 key，避免写穿复杂化；
   - **禁止**只改缓存不改 DB。
4. 测试与本地使用独立 Redis DB/实例前缀，避免污染。
5. 小程序本地缓存约定见 §7.7；服务端 Redis 约定以本节为准。

---

## 15. 安全基线

1. 所有用户 API 需登录（除健康检查与登录/刷新接口）。
2. **每一次**读取/变更 `task` / `asset` **必须校验 `user_id` 归属**，防止越权。
3. **创建任务**接口必须校验 **单用户最大排队/进行中任务数**（默认 ≤3）。
4. 上传 MIME 与扩展名双校验；Worker 再验魔数；COS key 清洗（§6.6）。
5. 管理接口独立鉴权，不放在小程序同域暴露。
6. 依赖锁定版本；禁止盲升大版本。
7. **依赖漏洞扫描**：CI 集成 **`pip-audit`**（小程序侧按需 `npm audit`）；**高危（high/critical）未豁免则禁止合并**；临时豁免须书面理由与到期日。
8. **小程序 XSS**：用户生成内容（角色卡、小说段落、错误回显等）优先用 **`<text>`** 等文本组件展示；**禁止**对不可信 HTML 使用 `rich-text` 渲染；若必须富文本，须白名单消毒并 CR 标明。
9. Token/密钥不进日志；CORS/域名白名单按微信小程序合法 request 域名配置。

## 附录 A. 推荐本地开发流程

完整步骤以 **[05-启动步骤](./05-启动步骤.md)** 为准。摘要：

```bash
uv sync
docker compose up -d mysql redis minio
uv run alembic upgrade head
uv run uvicorn oc_api.main:app --reload --port 8000
uv run celery -A oc_worker.celery_app:celery_app worker -l INFO -Q q.tools,q.ai
# 建议：TTL / 超时 sweep / 告警
uv run celery -A oc_worker.celery_app:celery_app beat -l INFO
# 微信开发者工具打开 apps/miniapp
```

**备注：**

- 本机跑 PDF 压缩需 `gs`；Word→PDF 需 `soffice`；也可用 compose worker 镜像（见 `docker-compose.yml`）。  
- 改过 Worker include / tools 后必须重启 Celery（不热加载）。
