# Office Craft — 数据模型与 MySQL DDL

> 文档版本：v0.3  
> 更新日期：2026-09-07  
> 对应蓝图：`docs/01-项目蓝图.md` §4.5；开发规范 §5.8 / §13  
> 引擎目标：MySQL 8.0+，`utf8mb4` / `utf8mb4_unicode_ci`  
> 迁移：`alembic/versions/0001_initial.py` + `0002_quota_pk.py`（见 §3.1 注意）  
> 表名说明：本版 DDL 使用短名 `quotas` / `assets`；开发规范 §3.1 约定**新增**关联表优先 `{主体}_{从属}`（如 `user_quotas`），二者不强制改名已落地表

---

## 1. 设计原则

1. **第三范式（3NF）**
   - 消除重复组：AI 消息、小说章节独立成表，不使用「消息数组/章节数组」大 JSON 作为主存储。
   - 消除传递依赖：文件内容属性（sha256、size、mime、cos_key）归入 `storage_objects`；`assets` 仅表达任务与对象的关系及用户侧文件名、TTL。
   - 额度与用户 1:1 分表，避免用户资料与计费字段混杂（逻辑清晰；非强制 3NF 要求）。
2. **对外 ID 与内部 ID 分离**：内部 `BIGINT` PK；任务等对前端暴露 `public_id`。
3. **敏感与诊断分离**：`tasks.error_detail` 仅服务端；用户文案由 `error_code` → `user_msg` 映射。
4. **JSON 使用边界**：仅存「非重复、弱结构」摘要（`input_meta`/`output_meta`/`payload_json`/`detail_json`）；禁止用 JSON 替代本可建表的 1:N 关系。
5. **对象 TTL**：`assets.ttl_expire_at` — 输入/未绑定默认 **6h**，输出默认 **24h**（与蓝图 §4.8、规范 §6.6 一致）。
6. **表字段基线**（规范 §13）：业务表含 `id`、`created_at`、`updated_at`；只追加审计表（如 `operation_logs`）可仅有 `created_at`。

## 4. MySQL DDL

```sql
-- ---------------------------------------------------------------------------
-- Office Craft schema (MySQL 8.0+)
-- ---------------------------------------------------------------------------

CREATE DATABASE IF NOT EXISTS office_craft
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

USE office_craft;

-- =========================
-- users
-- =========================
CREATE TABLE users (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  openid        VARCHAR(64)     NOT NULL COMMENT '微信 openid',
  unionid       VARCHAR(64)     NULL COMMENT '微信 unionid',
  nickname      VARCHAR(64)     NULL COMMENT '昵称缓存',
  avatar_url    VARCHAR(512)    NULL COMMENT '头像 URL 缓存',
  status        TINYINT         NOT NULL DEFAULT 1 COMMENT '1正常 0禁用',
  created_at    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_users_openid (openid),
  UNIQUE KEY uk_users_unionid (unionid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='用户';

-- =========================
-- quotas (1:1 users)
-- =========================
CREATE TABLE quotas (
  user_id            BIGINT UNSIGNED NOT NULL COMMENT 'PK/FK users.id',
  daily_quota_limit  INT UNSIGNED    NOT NULL DEFAULT 20 COMMENT '每日免费额度上限',
  daily_used         INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '当日已用点数',
  daily_used_date    DATE            NOT NULL COMMENT 'daily_used 所属日期(上海时区业务日)',
  total_used         BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '历史累计已用点数',
  frozen_quota       INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '预占未结算点数',
  vip_balance        INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '会员/加购余额',
  vip_expire_at      DATETIME(3)     NULL COMMENT '会员到期时间',
  updated_at         DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (user_id),
  CONSTRAINT fk_quotas_user
    FOREIGN KEY (user_id) REFERENCES users (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='用户额度账户';
```

> **实现注意（`0002_quota_pk`）：** `quotas.user_id` 为主键且**不得** `AUTO_INCREMENT`。Alembic/MySQL 若误加自增，会把本地 stub `user_id=0` 改写成 1、2、3…。升级请 `uv run alembic upgrade head`。

```sql
-- =========================
-- tasks
-- =========================
CREATE TABLE tasks (
  id                 BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  public_id          CHAR(26)        NOT NULL COMMENT '对外公开 ID',
  user_id            BIGINT UNSIGNED NOT NULL COMMENT 'FK users.id',
  type               VARCHAR(32)     NOT NULL COMMENT '任务类型',
  status             VARCHAR(16)     NOT NULL DEFAULT 'pending' COMMENT '任务状态',
  progress           TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0-100',
  error_code         INT             NULL COMMENT '业务错误码',
  error_class        VARCHAR(16)     NULL COMMENT 'user/system/timeout/safety',
  error_detail       TEXT            NULL COMMENT '内部诊断信息，禁止直接返回前端',
  retry_count        TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '已重试次数',
  cost_quota         INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '本单额度点数',
  quota_settled      TINYINT         NOT NULL DEFAULT 0 COMMENT '0预占 1已实扣 2已回退',
  input_meta         JSON            NULL COMMENT '输入参数摘要',
  output_meta        JSON            NULL COMMENT '输出结果摘要',
  idempotency_key    VARCHAR(64)     NULL COMMENT '幂等键',
  timeout_at         DATETIME(3)     NULL COMMENT '计划超时时刻',
  result_expires_at  DATETIME(3)     NULL COMMENT '结果业务过期时间',
  started_at         DATETIME(3)     NULL COMMENT '开始运行时间',
  finished_at        DATETIME(3)     NULL COMMENT '终态时间',
  created_at         DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at         DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_tasks_public_id (public_id),
  UNIQUE KEY uk_tasks_user_idempotency (user_id, idempotency_key),
  KEY idx_tasks_user_created (user_id, created_at),
  KEY idx_tasks_user_status (user_id, status),
  KEY idx_tasks_timeout (status, timeout_at),
  CONSTRAINT fk_tasks_user
    FOREIGN KEY (user_id) REFERENCES users (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='异步任务';

-- 说明：idempotency_key 为 NULL 时，MySQL 允许多条 NULL（不冲突）。
-- 应用层创建扣费任务必须传入非空 Idempotency-Key。

-- =========================
-- storage_objects (content-addressed, sha256 dedupe)
-- =========================
CREATE TABLE storage_objects (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  sha256       CHAR(64)        NOT NULL COMMENT '文件内容 SHA-256 十六进制',
  size_bytes   BIGINT UNSIGNED NOT NULL COMMENT '字节大小',
  mime         VARCHAR(128)    NOT NULL COMMENT 'MIME 类型',
  cos_key      VARCHAR(512)    NOT NULL COMMENT '对象存储 Key',
  ref_count    INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '被 assets 引用数',
  created_at   DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_storage_sha256 (sha256),
  KEY idx_storage_cos_key (cos_key(191))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='内容寻址存储对象（按 sha256 去重）';

-- =========================
-- assets (task ↔ storage_object)
-- =========================
CREATE TABLE assets (
  id                 BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  task_id            BIGINT UNSIGNED NOT NULL COMMENT 'FK tasks.id',
  storage_object_id  BIGINT UNSIGNED NOT NULL COMMENT 'FK storage_objects.id',
  kind               VARCHAR(16)     NOT NULL COMMENT 'input/output',
  original_filename  VARCHAR(255)    NULL COMMENT '用户原始文件名',
  ttl_expire_at      DATETIME(3)     NOT NULL COMMENT '业务过期时间',
  created_at         DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_assets_task (task_id),
  KEY idx_assets_ttl (ttl_expire_at),
  KEY idx_assets_storage (storage_object_id),
  CONSTRAINT fk_assets_task
    FOREIGN KEY (task_id) REFERENCES tasks (id),
  CONSTRAINT fk_assets_storage
    FOREIGN KEY (storage_object_id) REFERENCES storage_objects (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='任务资产关系；sha256 经 storage_objects 关联';

-- ai_sessions

CREATE TABLE ai_sessions (

  ref_type          VARCHAR(32)     NULL COMMENT '关联业务表',

  status            VARCHAR(16)     NOT NULL DEFAULT 'active' COMMENT 'active/closed',
  prompt_version    VARCHAR(32)     NULL COMMENT 'Prompt 版本',
  total_tokens_in   INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '累计输入 token',
  total_tokens_out  INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '累计输出 token',
```

## 5. 3NF 符合性说明

| 决策 | 做法 | 原因 |
|------|------|------|
| 文件去重 | `storage_objects.sha256` UNIQUE + `assets` 引用 | 避免在多条 asset 上重复存 size/mime/cos_key（消除传递依赖） |
| 小说章节 | `novel_chapters` 独立表 | 消除 `chapters_json` 重复组 |
| AI 消息 | `ai_messages` 独立表 | 消除会话内消息数组 |
| 角色卡正文 | `payload_json` 保留 JSON | 字段随 schema_version 演进；非固定列重复组，可接受；列表字段用 `title` 冗余仅作展示 |
| 额度日重置 | `daily_used` + `daily_used_date` | 不另建「每日流水表」亦可工作；若需强审计可后续加 `quota_ledgers`（非 MVP 必须） |
| 错误文案 | 不存 `user_msg` 列 | 由错误码表（代码/配置）派生，避免文案变更导致历史行不一致 |

**未采纳（有意弱化）**

- 未把 `input_meta`/`output_meta` 再拆成 EAV：收益低、查询复杂。
- 未强制 `character_cards.payload_json` 全列化：schema 多变，用 `schema_version` + JSON 更务实。

## 6. 与额度/任务的写入约定（应用层）

### 6.1 日重置（懒）

```text
IF quotas.daily_used_date < CURDATE_Asia_Shanghai THEN
  SET daily_used = 0, daily_used_date = today
END
```

### 6.2 预占

```text
available = daily_quota_limit - daily_used + vip_balance - frozen_quota
要求 available >= cost_quota
frozen_quota += cost_quota
tasks.quota_settled = 0
```

### 6.3 实扣 / 回退

与蓝图 §4.6、开发规范 §5.8 对齐：

```text
实扣(succeeded / safety 默认): frozen -= cost; daily_used += cost; total_used += cost; 不足部分扣 vip_balance；quota_settled=1
回退(system|timeout|cancel|用户文件类 user 错误): frozen -= cost; quota_settled=2（不扣费）
safety 内容安全拒绝: 默认转实扣、不回退（防刷审）；禁止静默丢预占
额度变更仅 API 执行；Worker 只回写 tasks/assets
```

### 6.4 Asset 写入与 sha256

1. 计算文件 sha256。  
2. `INSERT ... ON DUPLICATE KEY` / 先查 `storage_objects`：命中则 `ref_count+1`，可复用 `cos_key`（若策略允许秒传）。  
3. 写入 `assets(task_id, storage_object_id, kind, ...)`。  
4. 查询任务详情时 `JOIN storage_objects` 取出 `sha256`。

### 6.5 version 字段

- `character_cards.version` / `novel_projects.version`：本地编辑提交带 `If-Match`/`version`，冲突返回 409。  
- `novel_chapters.version`：单章级冲突控制。  
- 与 `schema_version`（结构定义版本）含义不同，禁止混用。
