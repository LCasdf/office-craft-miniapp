# Office Craft — 本地启动步骤

> 文档版本：v0.4  
> 更新日期：2026-09-07  
> 适用：M0 基建 + M1 工具（转 PDF / 压缩 / 合并；任务重试 / 下载 / 超时 sweep）  
> 前置：已安装 [uv](https://github.com/astral-sh/uv)、Docker Desktop、（可选）微信开发者工具  
> 进度见 [07-项目进度](./07-项目进度.md)

仓库根目录：

```bash
cd /path/to/office-craft-miniapp
```

## 日常启动（首次完成后每天用这个）

已有 `.env`、`.venv`、且数据库已迁移过时，只需：

```bash
# 1. 基础设施（MySQL / Redis / MinIO）
docker compose up -d mysql redis minio
# 或容器已存在时：docker compose start

# 2. 可选：依赖或迁移有变更时才跑
# uv sync
# uv run alembic upgrade head

# 3. 终端 A — API
uv run uvicorn oc_api.main:app --reload --port 8000

# 4. 终端 B — Worker（改过 tools 任务后必须重启，Celery 不热加载 include）
uv run celery -A oc_worker.celery_app:celery_app worker -l INFO -Q q.tools,q.ai

# 5. 终端 C — Beat（TTL 清理 / 超时 sweep / 基础告警；可选但 M1 建议开）
uv run celery -A oc_worker.celery_app:celery_app beat -l INFO
```

验证 API：

```bash
curl -s http://127.0.0.1:8000/healthz
# 期望含 "status":"ok"；根路径 / 无路由，返回 404 属正常

curl -s http://127.0.0.1:8000/metrics
# Prometheus 文本：清理计数、队列深度等
```

- Swagger：http://127.0.0.1:8000/docs  
- MinIO 控制台：http://127.0.0.1:9001（默认 `minioadmin` / `minioadmin`）  
- 小程序：微信开发者工具打开 `apps/miniapp`

结束：API / Worker 终端 `Ctrl+C`；基础设施 `docker compose stop`（数据保留在 volume）。

| 场景 | 要不要再跑 |
|------|------------|
| 日常开关机开发 | 只需 compose + API + Worker（**建议开 Beat**） |
| 拉了新代码、`pyproject` 有变 | `uv sync` |
| 有新的 alembic 版本 | `uv run alembic upgrade head`（含 `0002_quota_pk`） |
| 改了 `.env.example` 且本地还没有对应项 | 对照合并进 `.env`（尤其 `S3_*` / `COS_BUCKET` / TTL·告警） |
| 小程序工程未导入过 | 见下文「首次」第 7 步 |
| 跑 inflight 压测骨架 | `uv run python scripts/load/run_inflight.py --n 5`（API 需已起） |

## 首次启动（只需一次）

按顺序做完即可；之后走上面的「日常启动」。

### 0. 环境要求

| 工具 | 建议版本 | 用途 |
|------|----------|------|
| Python | ≥ 3.11（uv 会自动选用本机解释器） | API / Worker |
| uv | 最新稳定版 | 依赖与虚拟环境 |
| Docker | 可运行 `docker compose` | MySQL / Redis / MinIO |
| 微信开发者工具 | 稳定版 | 打开小程序工程 |
| LibreOffice（可选） | 含 `soffice` | 本机跑 Word→PDF；也可用 compose worker 镜像 |
| Ghostscript（可选） | 含 `gs` | 本机跑 PDF 压缩；也可用 compose worker 镜像 |

### 1. 配置环境变量

```bash
cp .env.example .env
```

按需编辑 `.env`（本地默认已与 `docker-compose.yml` 对齐）：

| 变量 | 说明 |
|------|------|
| `MYSQL_*` | 用户 `oc` / 密码 `oc_dev_password` / 库 `office_craft`；宿主机端口默认 **3307** |
| `CELERY_BROKER_URL` / `CELERY_RESULT_BACKEND` | 本机 Redis |
| `S3_ENDPOINT_URL` | 本地 MinIO：`http://127.0.0.1:9000` |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | 默认 `minioadmin` / `minioadmin` |
| `COS_BUCKET` | 桶名，默认 `office-craft`（首次上传时自动建桶） |
| `COS_ENV_PREFIX` | 对象键前缀环境段，默认 `local` |
| `JWT_SECRET` | 仅本地占位；**勿提交真实密钥** |

### 2. 安装 Python 依赖

```bash
uv sync
```

成功后根目录出现 `.venv/`。自检：

```bash
uv run pytest -q
# 或：bash scripts/dev_check.sh
```

### 3. 启动基础设施

```bash
docker compose up -d mysql redis minio
```

| 服务 | 端口 | 说明 |
|------|------|------|
| MySQL | **`3307`→容器 3306** | 库名 `office_craft` |
| Redis | `6379` | Celery broker / result |
| MinIO | `9000` API / `9001` 控制台 | 本地对象存储（结果 PDF 在这里） |

```bash
docker compose ps
# mysql / redis 应为 healthy 或 running
```

本机改代码推荐 `uv run celery ...`。可选：`docker compose --profile full up -d worker`（镜像含 Ghostscript + LibreOffice Writer）。

### 4. 数据库迁移

```bash
uv run alembic upgrade head
```

当前迁移：`alembic/versions/0001_initial.py`（`users` / `quotas` / `tasks`）。

### 5–6. 启动 API 与 Worker

同「日常启动」第 3、4 步。

#### M0 冒烟（空任务 ping）

```bash
curl -s -X POST http://127.0.0.1:8000/v1/uploads/credential \
  -H 'Content-Type: application/json' \
  -d '{"taskType":"character_card","fileCount":1}'

curl -s -X POST http://127.0.0.1:8000/v1/tasks \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 11111111-1111-4111-8111-111111111111' \
  -d '{"type":"character_card","inputs":[],"uploadId":"upl_demo"}'
```

Worker 日志应出现 `ping_task_start`；`GET /v1/tasks` 或任务中心可见 `succeeded`。

#### M1 冒烟（图片转 PDF → 下载）

```bash
uv run python -c "from PIL import Image; Image.new('RGB',(64,96),(10,80,160)).save('/tmp/oc.png')"

# 1) 凭证
UPID=$(curl -s -X POST http://127.0.0.1:8000/v1/uploads/credential \
  -H 'Content-Type: application/json' \
  -d '{"taskType":"image_to_pdf","fileCount":1}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["uploadId"])')

# 2) 上传到 MinIO（经 API）
COSKEY=$(curl -s -X POST "http://127.0.0.1:8000/v1/uploads/${UPID}/objects" \
  -F "file=@/tmp/oc.png;filename=a.png" -F "index=0" -F "taskType=image_to_pdf" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["cosKey"])')

# 3) 建任务
IK=$(uuidgen | tr 'A-Z' 'a-z')
TID=$(curl -s -X POST http://127.0.0.1:8000/v1/tasks \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $IK" \
  -d "{\"type\":\"image_to_pdf\",\"uploadId\":\"$UPID\",\"inputs\":[{\"cosKey\":\"$COSKEY\",\"filename\":\"a.png\"}],\"params\":{\"orientation\":\"auto\"}}" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["taskId"])')

# 4) 轮询至 succeeded；下载用独立接口（过期返回 40016）
sleep 3
curl -s "http://127.0.0.1:8000/v1/tasks/$TID"
curl -s "http://127.0.0.1:8000/v1/tasks/$TID/download"
# data.downloadUrl → 浏览器打开或 curl -OJ 下载
# 对象键：local/0/results/{taskId}/result.pdf（MinIO 桶 office-craft）
```

**结果 PDF 在哪**

| 方式 | 说明 |
|------|------|
| 小程序 | 任务中心 →「下载 PDF」（走 `/download`）；失败可「重试」；过期有文案 |
| API | `GET /v1/tasks/{taskId}/download` → `data.downloadUrl`（预签名，默认 ≤15min）；过期 `40016` |
| 详情兜底 | `GET /v1/tasks/{taskId}` → `data.outputs[0].downloadUrl`（过期则 `outputs=[]`） |
| MinIO 控制台 | http://127.0.0.1:9001 → 桶 `office-craft` → `local/0/results/.../result.pdf` |

Word 转 PDF：本机需 `soffice`，或使用 compose `full` profile 的 worker 镜像。

#### M1 冒烟（PDF 压缩 / 合并）

小程序首页进入对应工具页即可。本机压缩需 `gs`（`brew install ghostscript`），合并只需 pypdf（`uv sync` 已带）。

加密 PDF、损坏文件、合并超 200 页会 `failed` 且 `errorClass=user`（文案「含加密 PDF，请先解除保护」等）。结果下载同「结果 PDF 在哪」。

### 7. 导入微信小程序（一次）

1. 微信开发者工具 → 导入项目，目录选 `apps/miniapp`  
2. AppID 可用测试号 / `touristappid`  
3. 详情 → 本地设置：勾选「不校验合法域名」（API `8000` 与 MinIO `9000` 下载都需要）  
4. `miniprogram/app.js` 中 `apiBaseUrl` 为 `http://127.0.0.1:8000`（真机调试改局域网 IP）

## 常见问题

| 现象 | 处理 |
|------|------|
| `uv sync` 失败 | 检查网络与 Python ≥3.11；删除 `.venv` 后重试 |
| Alembic `Access denied for user 'oc'@'localhost'` | 多半连到了本机 mysqld。确认 `.env` `MYSQL_PORT=3307`；`docker compose up -d mysql` |
| Alembic `Invalid default value for 'created_at'` | 需 `DATETIME(3)`；拉最新迁移后再 `upgrade head` |
| Alembic 连不上 MySQL | `docker compose ps`；等 healthy；账号与 compose 一致 |
| Redis 端口占用 / compose 起不来 | 本机已有 Redis 占 6379 时可继续用已有实例，或停掉冲突进程后再 `compose up` |
| `GET /` 或 `/json/version` 404 | 正常：健康检查用 `/healthz`，文档用 `/docs` |
| Worker 无任务 / 一直 `queued` | Redis URL 一致；`-Q q.tools,q.ai`；**改过 tools 后重启 Worker** |
| 上传 `50001` / put 失败 | MinIO 未启；或 `.env` 缺 `S3_ENDPOINT_URL` / `COS_BUCKET`（改后需重启 API） |
| 转换成功但找不到 PDF | 不在相册；见上文「结果 PDF 在哪」 |
| 小程序下载失败 | 未勾选「不校验合法域名」；或 API/MinIO 未启动；真机需局域网 IP |
| Word 任务失败且无 soffice | 安装 LibreOffice，或用 compose worker 镜像 |
| 本机无 Ghostscript | `brew install ghostscript` 后重启 Worker；或用 compose worker 镜像（已含 gs） |
